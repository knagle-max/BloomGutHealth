# Food and supplement products

Product coverage is a lookup workflow, not a list of named brand exceptions. The journal retains its 5,431-food USDA FNDDS catalogue and generic household-portion parsing. Authenticated product search additionally queries Open Food Facts for packaged foods/barcodes and NIH DSLD for supplement-label candidates. It also searches private saved labels. Users select an exact product and labelled serving; ambiguous names never silently select another formulation. There are no brand-specific nutrition values in application code.

NIH labels can provide multiple servings and non-mass units such as capsules or gummies. The adapter uses only serving quantities explicitly attached to nutrient rows, including a known quantity inside a suggested range. It converts unambiguous mass units and vitamin-D IU. Folate DFE, vitamin-A IU/unspecified equivalents and unsupported units remain separate label ingredients rather than being mixed into food-total folate or vitamin-A RAE. Blend/active-ingredient weights are displayed separately, not added to macros a second time. No dosing advice is inferred.

Open Food Facts is attributed under ODbL and is contributor data. Source dates, brand, serving, original links and unknown nutrients remain visible. Search uses a submit button, bounded public-data caches, single-flight requests, timeouts and per-account/source rate limits. Third-party outages and missing products produce useful fallback states. API credentials are not required for these public lookups; existing optional USDA live lookup can still use a configured USDA_FDC_API_KEY. No service guarantees every product or current formulation in every country.

For a missing product, any signed-in user can enter the package's per-serving values and save a reusable private label. Empty values stay unknown; explicitly entered zero stays zero. Personal labels are encrypted using PRECISION_DATA_KEY, stored under the authenticated account and never published to shared databases. Apply additive migration `migrations/0003_nutrition_products.sql` before this release. Retain the existing encryption key. Product identifiers are resolved server-side on meal save/recalculation; values supplied by the client are not presented as verified database data. Existing meals keep their saved nutrition snapshot if a reusable label is later removed.

Recalculating an unmatched journal entry opens its nutrition review and searches product candidates. A save without a food match reports that nutrition still needs a match, rather than claiming that missing values were updated. Confirming a product and serving in this review immediately recalculates and persists the meal; subsequent recalculations retain that product reference and serving count. Closed journal reports do not mount product searches. Search retains formula phrases, checks a larger NIH candidate set and excludes explicitly sugar-free NIH labels when the query explicitly asks for a sugared formula. Users must still verify the exact label, market and amount; a heaping spoon does not establish a measured mass.

Selected labels can be logged alone or alongside described foods. They contribute the nutrients actually declared, including micronutrients without an energy value. Known daily contributions survive unrelated unknown nutrients or meals. Unsupported supplement ingredients can be recorded/displayed separately but are not diet-optimization targets. The label form supports the app's 21 nutrient fields and an additional ingredient; photo/OCR ingestion is not included.

Tests cover varied synthetic brands, powder/capsule/gummy serving forms, unit conversions and abstention, zero vs missing, arbitrary label creation and reuse, partial meals, source failure, bounded requests and cross-account isolation. Live NIH read-only checks additionally verified three different product/formulation records. Open Food Facts was inaccessible from the development network; its adapter is fixture-tested and exposes service failures instead of claiming a live verification.
