# Food and supplement products

Product coverage is a lookup workflow, not a list of named brand exceptions. The journal retains its 5,431-food USDA FNDDS catalogue and generic household-portion parsing. Authenticated product search uses a separate USDA Branded Foods adapter when USDA_FDC_API_KEY is configured, NIH DSLD for supplement labels, and Open Food Facts only when its explicit licensing flag is approved. It also searches private saved labels. Users select an exact product and labelled serving; ambiguous names never silently select another formulation. There are no brand-specific nutrition values in application code.

NIH labels can provide multiple servings and non-mass units such as capsules or gummies. The adapter uses only serving quantities explicitly attached to nutrient rows, including a known quantity inside a suggested range. It converts unambiguous mass units and vitamin-D IU. Folate DFE, vitamin-A IU/unspecified equivalents and unsupported units remain separate label ingredients rather than being mixed into food-total folate or vitamin-A RAE. Blend/active-ingredient weights are displayed separately, not added to macros a second time. No dosing advice is inferred.

Open Food Facts is attributed under ODbL and is contributor data. Source dates, brand, serving, original links and unknown nutrients remain visible. Search uses a submit button, bounded public-data caches, single-flight requests, timeouts and per-account/source rate limits. Third-party outages and missing products produce useful fallback states. USDA live generic and branded lookups require the existing USDA_FDC_API_KEY; the local FNDDS catalogue and private labels work without it. Open Food Facts remains independently licensing-gated. No service guarantees every product or current formulation in every country.

For a missing product, any signed-in user can enter the package's per-serving values and save a reusable private label. Empty values stay unknown; explicitly entered zero stays zero. Personal labels are encrypted using PRECISION_DATA_KEY, stored under the authenticated account and never published to shared databases. Apply additive migration `migrations/0003_nutrition_products.sql` before this release. Retain the existing encryption key. Product identifiers are resolved server-side on meal save/recalculation; values supplied by the client are not presented as verified database data. Existing meals keep their saved nutrition snapshot if a reusable label is later removed.

Recalculating an unmatched journal entry opens its nutrition review and searches product candidates. A save without a food match reports that nutrition still needs a match, rather than claiming that missing values were updated. Confirming a product and serving in this review immediately recalculates and persists the meal; subsequent recalculations retain that product reference and serving count. Closed journal reports do not mount product searches. Search retains formula phrases, checks a larger NIH candidate set and excludes explicitly sugar-free NIH labels when the query explicitly asks for a sugared formula. Users must still verify the exact label, market and amount; a heaping spoon does not establish a measured mass.

Selected labels can be logged alone or alongside described foods. They contribute the nutrients actually declared, including micronutrients without an energy value. Known daily contributions survive unrelated unknown nutrients or meals. Unsupported supplement ingredients can be recorded/displayed separately but are not diet-optimization targets. The label form supports the app's 21 nutrient fields and an additional ingredient; the existing optional photo transcription flow requires fresh affirmative consent and manual review before a label is saved.

Tests cover varied synthetic brands, powder/capsule/gummy serving forms, unit conversions and abstention, zero vs missing, arbitrary label creation and reuse, partial meals, source failure, bounded requests and cross-account isolation. Live NIH read-only checks additionally verified three different product/formulation records. Open Food Facts was inaccessible from the development network; its adapter is fixture-tested and exposes service failures instead of claiming a live verification.

## USDA Branded Foods and packaged-food incident follow-through

The versioned `usda-branded-v1` adapter queries only the Branded collection, resolves a selected FDC ID server-side and retains GTIN, owner, market country, source dates and formulation with the meal's analyzed snapshot. Name aliases (`KitKat`, `Kit Kat`, `kit kit bar`, Michelina's punctuation) affect search/ranking only; they do not select a different SKU or overwrite the original query. Barcode candidates must match the canonical GTIN. A US record is never represented as proof of a Canadian formulation. Explicit label servings and per-100g fallback are distinguished; volume is never converted to mass by guessing density.

Public cache misses are time/size/rate bounded. Missing credentials, licensing gates or source failures leave a direct package-nutrition entry path, with private reuse, serving review and known daily totals. No public/private database merge or OFF activation is introduced. `query` is an optional backwards-compatible product-reference field retaining the user's original search even when they explicitly use selected products as the whole entry.

Validation: 193 Node tests, TypeScript, production build, zero production dependency advisories and a [synthetic phone-sized journey](docs/review/branded-food-20261023/results.json). CI's existing isolated-database smoke test additionally checks saved-label spelling normalization and query persistence. Local USDA credentials are absent and OFF approval is false; real USDA Canadian coverage and current Render credential/connectivity are not claimed verified. OFF legal approval, live Canadian exact-SKU/bilingual/formulation benchmark and physical-device acceptance remain outstanding. No API keys or production credentials were changed.
