## The owner's non-negotiable standing instruction

For **every screen or component set**, supply a filled **UI Visual & Design Token Specification** so engineering implements deliberate hierarchy on the first pass:

1. **Elevation/contrast:** exact per-theme canvas, sheet/drawer, card, border, scrim, primary/secondary/muted text, interactive, selected and keyboard-focus visual tokens; no muddy low-contrast fields or surfaces.
2. **Typography/space/shape:** family, size, weight, line height and tracking for each text role; exact component padding, gap rhythm, radii, dividers and at-least-44px touch controls. Reconcile proposed values with approved code tokens.
3. **Full interactive-state specifications:** default, hover, focus, active/selected, pressed, disabled, loading and error for toggles, chips, forms, buttons, sheets and drawers. Non-color-only state indication.
4. **Anti-pattern guardrails:** reject unstyled form dumps, repetitive full-width nested bordered cards, low-contrast text walls and multiple competing CTAs. Preserve minimized premium botanical editorial presentation.
5. **Existing assets and science:** reuse approved BVA/CHART/REL/ONB artwork; preserve original vector geometry, chart data, mapped anatomy paths and source/rights contracts. Branding paint-layer design does not grant authority over UX structure or scientific interpretation.

**Acceptance documentation:** 320/390/768/1440px and four mode-theme combinations (Everyday Light/Dark; Athlete Light/Dark), 200% zoom, WCAG contrast evidence, visible focus, responsive safe areas, reduced-motion treatment, actual screen verification at current SHA and accessible/source-functional regressions. For high-impact UI implementation, the existing Architect/Codex handoff additionally mandates real 390×844 and 1440×900 screenshot inspection. Distinguish design approval from integrated and independently verified runtime.
