# V06-EXP-01 — existing capability workspace

The existing account-scoped preference now presents a compact categorized workspace
inside Profile → Account, adjacent to appearance and sign-out. There is one
preference, default OFF. Ordinary accounts receive no control or catalogue.

The server projects only explicit sanitized metadata scope, plus the pre-existing
synthetic food-photo preview scope. This is not the 52-entry Legal administration
manifest. Unknown IDs, incident-disabled entries, rejected/suspended approvals,
invalid grants, stale preference fingerprints and denied environments are hidden.
No model execution, new service, permission database or generic run endpoint was added.

`metadataPreview` is an optional **trusted server provisioning** field in the
existing internal grant. Its purpose is `development-status-review`; its features
are unique IDs from the bounded shared display-ID list. It grants status visibility
only. It does not widen `uiPreview.features`, `allowedCapabilities`, consent,
clinical/research permissions or public approval. Changing scope changes the
fingerprint and leaves old saved preferences OFF. Existing temporary and standing
scopes without the new field preserve their exact serialized fingerprints.

Only the separately granted existing local synthetic food-photo preview has an
action. That action refreshes current account-scoped server eligibility before
opening the exact allowlisted `/log-meal?method=photo` route. OFF, account change,
query failure or revocation removes entries; existing object-URL and restricted-query
cleanup remains. Informational/restricted entries have no navigation or execute CTA.
No actual account, environment grant or hosted service configuration was changed.

Local evidence: actual App → authenticated HTTP → isolated SQL preference storage;
17 viewport/theme/mode/zoom states, fresh action-time revocation denial, keyboard,
44px preview target, ON/OFF, foreign account, deep-link rejection, local image
cleanup and manual canonical food save. Failed-OFF persistence/retry also passes.
The old failed-OFF fixture first referenced a now-collapsed food chooser; its test
now uses the existing visible method-disclosure helper, retaining all denial,
retry and no-model-call assertions.

Everyday and Athlete are the installed modes tested. No Coach mode, VoiceOver,
physical iPhone, independent visual approval, hosted SHA or CI pass is invented.
Hosted/CI/deployment verification is pending because deployment remains forbidden.
This is local engineering evidence, not public activation or final v0.6 RC sign-off.
