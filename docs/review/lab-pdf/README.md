# LAB-03 local text-PDF intake

Engineering increment of the approved document-extraction/review requirement. Text PDFs can load into the existing editable lab source draft. Loading and previewing never saves records; manual source date, source-only row choice, units/provenance review and final save remain explicit. Printed identifiers are never inferred from filenames or PDF metadata. Clinical zero and exact text numbers/thresholds remain intact; ambiguous columns/order require edits. Existing `pasted-report` capture denotes the reviewed source-text pipeline, not an assertion of OCR accuracy.

Bounds: PDF extension and exact byte length, nonempty up to5MiB, PDF magic, five pages,30,000 extracted characters and20-second deadline. Output is not truncated. The existing parser separately enforces50 rows. Invalid/blank/scanned/protected/malformed/unsupported documents show static errors and retain the prior draft. Scanned PDFs have no OCR support in this increment; use manual entry or a text export. LAB-03 is not globally closed and no independent clinical/source-layout/device acceptance is claimed.

PDF.js6.4.299 (Apache2.0) is lazy-loaded with a hashed same-origin module worker. An explicit native Worker port prevents main-thread fallback; bytes go to that local worker, not a document URL/server/provider. No PDF rendering, actions, metadata identification, font-face loading, image decoding or external resource URL configuration is used. Worker and loading task are disposed after success/error/abort. A newer file and unmount abort the earlier PDF operation, and the existing epoch/account/mount/start guards prevent stale draft replacement. The development server pre-optimizes the lazy dependency so first use cannot reload and erase an active draft. Production emits the codec and worker separately; no PDF package is imported by server routes. Public Apache licence/attribution are retained under `/licenses/`.
