## Exact current source and root cause
Source-checked `enhance/bloom-experience`:
- `shared/additional-lab-markers.ts` includes **`psa_total`**, with accepted **"total PSA", "PSA total", "total prostate specific antigen"** etc., and `ng/mL` plus `ug/L` as equal physical units. No generic PSA-family supported ID.
- `shared/lab-source-identity.ts` deliberately returns `{ambiguous:'Confirm total PSA versus free PSA or a ratio ...'}` for exact bare `psa` or `prostatespecificantigen` before scanning known aliases. This preserves subtype safety, but UI conflates **known analyte family** with **unknown assay subtype**.
- `shared/lab-paste.ts` responds to ambiguous marker by rejecting supported canonical mapping; original source may survive as `sourceOnlyLabs`. `shared/lab-explorer.ts` groups exact original source labels into `other` entries. `client/src/components/LabExplorer.tsx` reports "marker not identified", and `LabMarkerEducation.tsx` says "The source label does not establish a supported analyte identity" even though generic PSA family is known.
- `shared/lab-assay-identity.ts` already prevents treating free/ratio labels as total in `hasConfirmedLabIdentity('psa_total', ...)`. Do not weaken this check.
- User's displayed record: source label **PSA**, **0.5 ug/L**, collected **2026-08-09**. Original source method/lab **Not supplied**, subtype unspecified. This screenshot-like text **does not prove total PSA**. 0.5 ug/L equals 0.5 ng/mL numerically.
