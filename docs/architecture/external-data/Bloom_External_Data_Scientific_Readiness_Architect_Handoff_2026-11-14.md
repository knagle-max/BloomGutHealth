1. Dependency tiers and minimum product capability

• T0 — indispensable to accurate core outcomes: owned food/meal/activity/goal data; locally available generic food nutrient composition with identity and units; reviewed appropriate nutrient reference values; lab identity/units/source and report-specific ranges; reviewed lifestyle/intervention evidence + approved actionable rules; temporal/provenance/consent; baseline deterministic ranking. Without these, Bloom can only give generic advice, not source-accurate nutrition or biomarker interpretation.
• T1 — high-value enrichment, not required for goals-only use: branded Canadian food lookup, manufacturer label records, complete micronutrient composition, a broader curated lab marker/relationship library, workout evidence, repeat assessments, optional health-device feeds, genetic annotation, taxonomic and pathway claims, supported experimental-context history.
• T2 — research and advanced interpretation: full-scale genetic association/effect metadata, microbial species/strain reference genomes, enzyme/reaction/chemical graphs, microbial reconstructions, ingredient-specific substrate chemistry, metabolomics reference distributions, independently benchmarked personal-response modeling. Absence must not block T0.
• T3 — conditional provider integrations: commercial restaurant products, real-time wearable or clinical-provider APIs, clinical datasets under additional rights/credentials, licensed proprietary sequence/omics resources, premium LLMs. Default off until legal, provider and privacy gates pass.

Delivery principle: use authoritative versioned local snapshot for computation; use read-only server-side API for bounded lookup/incremental discovery where justified; use human-reviewed local claim tables for intervention interpretations. Importing a publication is not approval of its claim. Never call third-party research APIs per user request with personally identifiable health/genomic records.

6. Genuinely important decision-data coverage requirements (mostly refinements, NOT duplicate services)

D01 — Biological context timeline: Reuse owned date-aware records/annotations for diet-pattern changes, actual physical activity, weight, medication/supplement changes (self-reported, no auto drug changes), relevant illness, fasting status and pre-collection context. Preserve occurredAt versus recordedAt, uncertainty and absence-as-unknown. One relevant high-information question at a time; don’t solicit every variable by default.

D02 — Representativeness: A food-log known subtotal is not usual intake, and an unlogged dinner is not zero. Explicit source-food-nutrient coverage and day coverage; assess whether the recorded period is representative before interpreting apparent adequacy. Keep confirmed supplement ingestion separate from scheduled/planned. Never derive biomarker status directly from estimated dietary intake.

D03 — Scientific knowledge coverage: Maintain a view or index over existing approved claim/knowledge records: domain, exact entity and identifier, relation, studied model/strain/population, effect direction/magnitude where supported, contradictory/null evidence, date, applicability, action permission, review status, source IDs, rights, and whether user input is sufficient. Show supported/partial/unsupported; do not inflate counts with unreviewed mechanism edges.

D04 — Information gain: Existing cross-domain ranking should ask what missing information would change an action/eligibility/interpretation. Example: fasting conditions of compared TG measurements, medication timing, usual missing meal, formula product. A missing genetics variant need not be requested if no decision-changing credible action exists. No compulsory speculative data collection or expensive testing.

D05 — Cross-domain prioritization: Continue binding deterministic safety-first ranking with fair candidate generation and evidence strength separate from personal-data reliability. One top action + up to three nonredundant alternatives with why-first, why-not-alternative, actual feasible path, population evidence and known limits. Lab safety-relevant findings require reviewed appropriate professional-discussion logic, not a wellness weighted-score shortcut.

D06 — Reference-data completeness: Test which requested computations require source-specific micronutrient, fatty-acid, amino-acid, fiber type, food-form or assay values unavailable in the adopted corpus. No blanket conversion from known calories/macros to exact missing micronutrients; no model-driven filling without labelled estimate and validated method.

Identity is a type, not a string guess: FDC food != CNF food != branded GTIN; LOINC property/system/method all matter; rsID/build/allele/haplotype are distinct; taxonomy names are not genome-resolved strain identifiers; CHEBI IDs do not collapse stereochemistry; Rhea reaction flux is not measured concentration. 8.6 Operable local-first source job pattern

// Illustrative pure boundary pattern — adapt to Bloom's existing source and manifest API.
async function stageProviderSnapshot(source: SourceConfig, fetcher: ProviderFetch) {
  const bytes = await fetcher.fetchBounded(source.url, {
    maxBytes: source.maxBytes,
    timeoutMs: source.timeoutMs,
    userAgent: source.userAgent,
  });
  const parsed = await source.adapter.parse(bytes);        // schema + units + provenance
  const report = await source.validator.validate(parsed); // IDs, semantics, QA fixtures
  if (!report.pass || !source.rightsApproved) return {activated: false, report};
  // Stage immutable rows, manifest, checksum and review receipt.
  // Activation must be transactional and reversible; old snapshot remains for replay.
  return source.canonicalStore.activateReviewedSnapshot(parsed, report);
}

9. Minimum scientific coverage and acceptance matrix

Architect to make a single matrix reusing existing capability registry and issue IDs; each row must have: feature; required user observations; required public/reference dataset; exact edition; permissible API/local mode; identity joins; required reviewed evidence; licence; uncertainty/missingness; supported action; offline fallback; tests; owner; deployed availability; source+commit receipt.

Mandatory test fixtures and expected results:

1. Goals-only: no lab/omics/wearable/food source ⇒ feasible evidence-backed general Today action, not invented personalized cause.
2. Canadian breakfast/lunch to dinner: available credible nutrient totals ⇒ specific dinner with verifiable ingredients/grams/portions, food exclusion hard veto and direct editable existing meal review; no auto-logged eaten event.
3. Missing iodine/choline etc. in label ⇒ documented nutrient unknown, not zero, not nutritional deficiency, not exact DRI adequacy.
4. Food composition conflict: two data versions or branded market variants disagree ⇒ user sees source decision; original consumed snapshot retained, no invisible retrospective rewrite.
5. Supplement: planned but not consumed ⇒ zero recorded contribution to actual intake, not zero biological status; proper form and elemental distinction before UL disclosure.
6. Full Canadian 30+ lab report: every original row preserved; multiple observed marker families considered; relevant non-TG issue can lead. Trend comparability requires assay/specimen/method/date compatibility; other markers remain visible even when unreviewed.
7. Lab context: retrospective diet/medication/fasting response collected with occurredAt/recordedAt distinction; post-draw exposures excluded; source correction retracts derived output.
8. Genetics: APOE one SNP absent other ⇒ no fabricated isoform; palindromic allele/build unknown ⇒ do not flip; correlated FADS variants not compounded into independent effects; source remains browseable.
9. Microbiome qualitative report: potential SCFA producer educational reference may display; numeric SCFA flux/abundance and microbial-produced vitamins not created; unpublished/unknown substrate links withheld.
10. Molecular research: one source-strain–enzyme–Rhea–ChEBI reaction map and producer/consumer scenario with explicit constraints, mass balance, negative controls, sensitivity and licence receipt; results stay research-labelled.
11. Cross-domain ranking: two goals, sparse food but more activity sources ⇒ no measurement-count bias; evidence strength separate from personal reliability; one realistic action and explained alternatives.
12. External outage/retraction: provider API offline ⇒ current approved local snapshot works; source retraction withdraws affected approved claims and explanations; no stale personalization.
13. Rights gate: commercial blocked OFF or restaurant vendor ⇒ cannot be activated by mere API success/flag; manual/saved foods still work.
14. Privacy: no raw user DNA/Viome PDF/lab source is sent to reference APIs; deleting source, changing account or consent removes derived active displays.
15. Actual human task test: use mixed goals-only/food/activity/lab/omics participants; ordinary user identifies action, source, uncertainty and alternatives; PASS requires real session evidence, not synthetic test label.

For advanced features also report scientific benchmark sensitivity, participant-held-out generalization, subgroup applicability and uncertainty. No generic health-optimization score or claim of largest personal causal benefit based only on a weighted formula.
