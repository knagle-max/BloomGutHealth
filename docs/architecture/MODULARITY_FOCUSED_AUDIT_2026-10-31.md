## Minimal remediation order
1. **P0 only if exposed:** account-scoped source reads/write and restricted feature direct-API/worker negative tests; fix demonstrated leak or unavailable core workflow.
2. **P1:** run checked-in import-graph scanner (commit `4a8fe3c`) and retain full output in CI artifact; fix real layer violations or harmful cycles; leave harmless cross-domain imports as documented.
3. **P1:** nutrition totals semantics fixture and cross-view parity; reconcile duplicate calculation implementation only if actual output difference or ambiguous contract, preferably within existing functions.
4. **P1:** optional capability-off smoke for no AI, research, microbiome, Coach and wearables across Food→Today→Progress, Athlete, basic planner. No new services or feature flags beyond existing controls.
5. **P2:** extract small optional interfaces for actual planner→research brittle import points; keep current monolith and canonical storage facade.

## Execution limitations and evidence standard
This review sampled source dependencies from actual branch via GitHub; did not execute Node scanner, tsc, unit tests, full browser application or exhaustive API authorization tests. Therefore **no definitive statement of zero cycles, complete tenant isolation, successful disabled-mode or safe deployment**. Script is structural and uses a simple static import matcher; dynamic imports, alias types and runtime effects may require manual confirmation. Codex should run it on checked-out branch, verify baseline, and integrate into focused CI only after identifying legitimate pre-existing exceptions. Not a pretext for substantial v0.6 architectural refactoring; core-first remains binding.
