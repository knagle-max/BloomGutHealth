# Architect P0 — report-level laboratory reference overlay and missing chart lines (2026-11-09)

**Owner-reproduced functional/UX defect. Implementation owner Codex.** The owner sets reference overlay per individual result and tries LifeLabs → SK, BC and ON; no range lines appear. Approval: fix existing panel/source-scoped overlay and the UI's unsupported-provider promises without relaxing scientific identity protections. Integrate with existing v0.6 lab P0 issues #5, #8 and #9; do not create parallel lab registries, provider pseudo-data, fabricated patient interval or new owner gate.

## Source inspection — confirmed cause, not conjecture
- `client/src/components/LabTrend.tsx` constructs `const [overlay,setOverlay]=useState(emptyLabOverlayChoice)` **inside every marker chart**, resets source context on selected point change. This is only local ephemeral presentation and cannot apply a single provider choice to all tests of a recorded panel.
- `shared/lab-provider-ranges.ts`: `publishedLabRanges: readonly LabRange[]=[]` **is empty**. It contains pending external references for **BC/ON** but no independently verified numerical interval rows; **SK has no provider entries**. Thus selecting LifeLabs/BC/ON/SK necessarily produces no provider chart lines, regardless of UI selection. These are not verified provider range datasets.
- `matchProviderRanges` intentionally requires verified exact source/province, analyte, specimen, assay, method, collection date, age at collection, applicable sex category, fasting, compatible units. These safety rules are sound; **do not remove them to make a graph look populated**.
- The chart SVG **already supports** reference bands and dashed bounds when `commonInterval` is actually supplied; `sourceReferenceIntervalForPlot` can plot **original report limits** when the saved row has correct reported lower/upper bounds, source identity and units. The chart rendering is not proved defective in the absence of an applicable range. Source-only/unverified assay cannot be silently charted.
- `LabSourceHistory` uses `groupLabHistory` grouping by actual import identity, with `groups.imports` and `groups.unlinked`. **A shared date by itself is not proof of one panel or specimen.** Existing `sourceReport.importId` plus report/specimen identity and original source dates should determine scope.

Choose `Original report` / `LifeLabs comparison` / `Other verified provider comparison` / `None`. A provider + province choice is a **comparison preference** across every scientifically eligible marker from that actual import group. The selected provider is NOT automatically assigned as the recorded laboratory. Preserve each source record's actual original identity. For distinct separately imported reports (even same date), independent settings; historical results not retroactively assigned to same panel.
2. **Scope/ownership:** Reuse canonical import IDs, authenticated source group and existing corrections. No user-owned settings silently bleed across account, collection, multiple same-day specimens, timezones, or source deletion. Determine whether to persist a small owned `reportOverlayPreference` associated with import ID (rather than pretending preferences are lab observation measurements) and/or view state; if persisted, protect per-owner, revision/invalidation, deletion/reimport, idempotency and cross-device continuity. Avoid overwriting immutable original intervals or making an official source claim.
3. **Charts:** When rendering an eligible marker from a selected report, use the report's overlay context and corresponding date-specific *original* result. Show verified `low/high` bands + dashed boundaries, clearly labelled source/provider/province/year/test and units. One-sided legitimate bounds are lines; decision limits are NOT normal bands. For trends containing several reports with different applicable reference intervals, display per-result scoped interval only (or separate plotted segments) rather than stretching any one provider interval across incompatible dates/labs/assays. Chart must visibly update on selection, no selection point required to activate a report-level preference when selected report has unambiguous context.

Incomplete coverage shows explicit test-level `No verified LifeLabs SK reference interval available` and reasons. UI should not offer selectable combinations as though working when no coverage exists; disable/show availability, or explain clearly before selection. Option `Original report` must use actual saved report reference intervals where present; if missing, offer reviewed manual bounds from original source, not guessed ones.
5. **Pipeline:** tie overlay to report-level scope at import/save/reload/history and chart rendering. Maintain source-only results as original source and preserve identical text/unit/date; never convert unsupported analyte blindly or make claims off an unreviewed source interval. Provider switch may change a *display-only comparison*, not laboratory provenance or recommendation/normal flags, without separately reviewed rule.

Tests must verify SVG `data-reference-limit` and accessible numerical label in actual browser. Explicit status if provider catalogue absent.

Avoid asserting the live user experience is fixed until deployed and actually tested.
