## Binding owner decision / execution principle
**Treat each gate as a small, finishable work item, not a reason to stop.** Codex has permission to find prior receipts, run missing focused tests, fix demonstrated defects, deliver evidence for scoped reviewer judgment, consolidate actual signoff decisions, update **existing** versioned capability policy where approved, push/test authorized review/development environment, and record completion. **No “please approve” owner checkpoint** for routine changes; perform the work. A provisional 2026-11-09 source-map `REVIEW_REQUIRED` does not demote a newly verified current-SHA feature to absent or globally blocked. Reuse passing prior evidence only when relevant source, binary/behavior, outputs, audience and deployment context remain equivalent; retest only material deltas. Do not build a new feature simply to close an evidence gap.

**Risk separation, not fake approval:**
1. **Routine source-faithful capture/search/edit/arithmetic/neutral display:** complete real engineering tests and existing required source/UX/privacy checks; request *only applicable* scoped specialist decisions, reusing prior signed reviews where valid. Don't require a fresh ML panel or physician opinion for every recorded food or source value.
2. **Reviewed general wellness/educational claims:** bind actual claim/output IDs, target population, evidence and limitations; obtain applicable Biology and other named reviewer judgment before exposing new wording.
3. **Consequential diagnoses, treatment/dose, prognostic/personal biological prediction, restricted research, paid-provider APIs and cross-user data:** **stay OFF** until their **specific independent qualified/legal/security/consent** authorizations exist. A release candidate and process review cannot waive these.
4. **Partial approval is useful**: enable tested logging, source inspection, actual historical measurements, user corrections, or clearly qualified descriptive lab arithmetic even if a higher-risk interpretation on the same page remains disabled. A failure in one provider format or unlicensed optional vendor blocks only that path.
5. **No broad feature switch:** never set a provisional Legal registry flag or `GENERAL_RELEASE` status solely to pass tests. Effective server/route/API authorization and correct audience, territory, purpose and test environment determine real availability.

Per capability record fields: `capabilityId`, `candidateSha`, `deploymentId`, `implementedUiApiOutputs`, `authorizedAudienceTerritoryPurpose`, `sourceProviderVersion`, `priorEvidenceRef`, `sameScopeAndBinary`, `materialDelta`, `fixturesExpectedActual`, `testsPassFailNotRun`, `outputClaimsApproved`, `outputClaimsRestricted`, `primaryReviewer`, `reviewerDecisionsByDomain`, `independentLegalSecurityConditions`, `architectConsolidatedDecision`, `serverPolicyChangeSha`, `negativeAuthorizationReceipt`, `reviewDeploymentSha`, `publicProductionReleaseStatus`, `nextActionOrExactBlocker`. **No blanket `approved: true` from file paths or docs alone.**

Closure dispositions should read:
- `REVIEWED_SCOPE_ENABLED`: actually permitted in named environment and verified end-to-end at exact SHA, excluded risky outputs withheld;
- `SCOPED_FIX_AND_RETEST`: reproducible failing test and minimal repair;
- `EVIDENCE_PACKET_READY_FOR_NAMED_REVIEW`: working implementation and complete packet, independent reviewer judgment pending;
- `RESTRICTED_INDEPENDENT_AUTHORIZATION`: defined clinical/legal/privacy/rights scope requires actual permission, safe independently useful functionality may continue;
- `NOT_IMPLEMENTED`: cannot prove existing implementation; leave roadmap item open, don't invent success;
- `ALREADY_VERIFIED_NO_CHANGE`: existing current-SHA evidence and permission suffice; close administratively, no code churn.

**No owner acceptance gate for each feature:** continue to qualified integrated RC for owner review. Independently necessary professional/legal/sensitive approvals still apply, and a reviewer response must be authentic. This file is an actionable instruction to produce evidence, fix issues, submit for appropriate signatures and implement **ready safe scopes now**, not merely an instruction to add more planning documents.
