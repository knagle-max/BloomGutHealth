# Bloom — Chart-First Bloodwork Reference Ranges
**Owner-directed P1 existing v0.6 UX correction · 2026-11-16 · Codex implementation · no intermediate owner/specialist review.**
**Status:** Requirements/source audit only; no code, CI or deployed UI acceptance asserted.

## Goal
**Biology → Bloodwork → illustrated category → marker → historical chart** must immediately communicate the observed value, any applicable **original report reference range**, source and units. The ordinary path must NOT require opening report-level overlay settings, activating a report or learning Bloom's internal matching scheme. Advanced source management remains available as an optional drill-in. This is a focused UI/selection correction, not new range science, medical interpretation, or another graph engine.

## Source inspection / likely root cause
At current review-branch state:
- `client/src/components/LabTrend.tsx` already renders source-range bands (`[data-reference-band]`), one-sided limits (`[data-reference-limit]`), accessible text, source point selectors and published comparisons. `shared/lab-reference-interval.ts` validates source intervals/units and `canShareSourceReference` prevents a dishonest full-history range.
- `shared/lab-overlay-preference.ts` defaults to `provider:'original-report'` and explicitly permits `'none'`. These are essential to preserve.
- **UI selection gap:** `LabTrend` `selectedPoint` depends on optional requested point and/or currently activated report, with single-point fallback only under a matching active report. Thus a chart can have several source points with intervals but **no selected point and no visible original interval**; active-report choice can cause the current marker to be unmatched. Do not assume adding a toggle alone fixes this.
- `client/src/components/LabReportOverlayControls.tsx` has report activation and provider controls inside `LabReportOverlayPanel`'s collapsed `<details aria-label='Report reference overlay preferences'>`; this works for advanced report setup but is not a suitable required path for routine viewing.
- `LabRangeSelector` already supplies provider, province and collection-context inputs; `LabTrend` currently mounts only `contextOnly` and only after a provider is already selected. Implement a compact chart-facing selector that reuses existing service/state rather than embedding a second overlay controller.
- `scripts/qa/report-range-overlay-journey.mjs` covers synthetic source-reference invariants and the old manual workflow. Adapt tests to the **new user-visible chart journey** rather than merely a fixed historical heading; preserve all real safety assertions.

## Required interaction / source selection state
1. **Default display:** when a marker has available compatible source points, choose a deterministic **latest eligible recorded observation for chart context** (with an explicit accessible label and date), subject to actual owner/report/revision/identity; default a usable source interval for that observation if available. If the latest point is not usable but an earlier point is, **do not silently present the earlier interval as the latest**: either show latest with “No reference range was provided with this result” and offer the prior recorded point, or explicitly identify that an earlier dated point was selected; choose behavior that best maintains user-visible truth. If multiple points share timestamp, do not silently choose an arbitrary one as definitive: preserve occurrence selection and explain ambiguity.
2. **Original report first:** no provider confirmation or report activation required merely to display an *already recorded* and source-compatible original interval. Resolved plotted interval is either verified shared across all compatible report observations, **or selected-result-scoped and visually localized**; never a band across incompatible reports/methods/dates. One-sided upper/lower stays one-sided. Where units or assay identity fail, show source-only and reason, not a fake range.
3. **Visible chart control:** place adjacent to chart (above preferred): `Show reference range` (default ON for applicable unsuppressed original; checked state reflects actual display) plus `Reference source` with `Original report`, `Published comparison` (only if a relevant provider option is supported), `None`. The toggle and source choice must not conflict; off must be represented as/behave like `None` in the existing overlay model, with a predictable way back to original or the last permitted published choice.
4. **Persistence rule:** any explicit saved **None** remains authoritative after reload. A user's saved report preference and source-scoped record/confirmations take precedence over defaulting; missing saved preference should use original-report default without writing to clinical records. State updates shown immediately and sourced through existing `useLabReportOverlays` mechanisms. Distinguish session-only selection vs persistently saved report preference. If `reportKey` genuinely absent, provide session-only original display using the selected source point with no invented report association; no cross-report preference propagation.
5. **Published comparison within chart:** rehost or reuse `LabRangeSelector` with focused provider and province options beside chart; context subpanel collapsed unless needed for relevant choice. Show provider, jurisdiction, date, citation and provisional status, distinguish reference interval vs clinical decision limit vs threshold; avoid implying performing laboratory identity. Existing source-specific confirmation/revision invalidation and no unknown-age/specimen inference remain mandatory. **Original source precedence remains:** do not replace an applicable original interval with an external comparison, even when user chooses the latter; make explanatory label clear.
6. **Clear no-data states:** if selected result has no original interval, say **“No reference range was provided with this result.”** If bound is present but unsupported/incompatible, explain the actual reason instead of “not supplied.” If selected report has no current occurrence of marker, keep the truthful source message and offer a current observation, not range borrowing. All options are labelled, not color-only; avoid green/red clinical verdicts.
7. **Advanced management:** retain `LabReportOverlayPanel`, original report/source and data correction, reviewed collection demographics, report matching, saved preferences and provenance behind a clear `Manage report and reference sources` disclosure/link. These controls are not prerequisites for original range display.

## Critical implementation constraints
- Keep **one canonical overlay preference/service and source projection**. Avoid an independent boolean, second database, new live range lookup engine or different rules inside chart/Atlas. Resolve distinction between `overlays.state.active` and a contextually chosen display point; avoid changing active-report global state solely on initial chart render, since unrelated reports and marker views may share the controller.
- `LabTrend.tsx`, `LabRangeSelector.tsx`, `LabReportOverlayControls.tsx`, `LabExplorer.tsx`, `BloodworkAtlas.tsx`, `shared/lab-reference-interval.ts`, `shared/lab-overlay-preference.ts`, `shared/lab-provider-ranges.ts`, existing `@/lib/lab-report-overlays` (resolve real file path from app) are the reusable components. Confirm current HEAD after any active CI repair before editing.
- Preserve source identity, immutable revisions, two reports on same date, original and converted units, assay/specimen/method/fasting comparability, one-sided bounds, clinical decision limits, provisional citations and account/consent restrictions. Never write presentation defaults back to observation records or infer missing source attributes.
- Use established botanical scientific-chart visuals, translucent accessible bands, labels/boundaries/units, selected result provenance, 44px touch/focus target, keyboard/screen-reader and 200% scaling, 320/390/768/1440, light/dark/forced colors, Athlete blue (without changing data behavior). Do not generate new images or change all Bloodwork navigation.

## Targeted tests and end-to-end completion
**Happy:** Direct-open marker with **one valid original** → selected result, labelled original band and exact endpoints **without opening report panel**. Several truly compatible same-report points → proper shared original band. Several incompatible report groups → selected-point-only bounds and clear date/lab source. Switching recorded point changes bounds immediately; one-sided interval produces limit line only. Explicit saved None after reload stays hidden; unsaved default does not overwrite any saved preference. Visible Show toggle and source selector are usable by touch/keyboard; relevant provider+province chooser previews eligible labelled comparison in chart, session-only provenance upheld.
**Negative:** Missing interval, parsed but incompatible bounds, source review pending, mixed assay/units, duplicate timestamp/occurrence, original vs verified/provisional external range, clinical decision limit only, unknown method/specimen/demographic, source deletion/revision/withdrawal, report A/B same date, account A/B no leaks. Verify original range always has priority when applicable and a saved None genuinely suppresses it.
**Visual:** source-backed actual points, labels, values and units in chart with no accidental full-range bands or no-data = zero; responsive mobile/tablet/desktop, Everyday light/dark, Athlete treatment, 200%, reduced motion and actual keyboard semantics.
