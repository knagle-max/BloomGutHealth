# Bloom — Chart-First Bloodwork Reference Ranges
**Owner-directed P1 existing v0.6 UX correction · 2026-11-16 · Codex implementation · no intermediate owner/specialist review.**
**Status:** Requirements/source audit only; no code, CI or deployed UI acceptance asserted.

## Goal
**Biology → Bloodwork → illustrated category → marker → historical chart** must immediately communicate the observed value, any applicable **original report reference range**, source and units. The ordinary path must NOT require opening report-level overlay settings, activating a report or learning Bloom's internal matching scheme. Advanced source management remains available as an optional drill-in. This is a focused UI/selection correction, not new range science, medical interpretation, or another graph engine.

## Source inspection / likely root cause
At current review-branch state:
- `client/src/components/LabTrend.tsx` already renders source-range bands (`[data-reference-band]`), one-sided limits (`[data-reference-limit]`), accessible text, source point selectors and published comparisons. `shared/lab-reference-interval.ts` validates source intervals/units and `canShareSourceReference` prevents a dishonest full-history range.
- `shared/lab-overlay-preference.ts` defaults to `provider:'original-report'` and explicitly permits `'none'`. These are essential to preserve.
- **UI selection gap:** `LabTrend` `selectedPoint` depends on optional requested point and/or currently activated report, with single-point fallback only under a matching active report. Thus a chart can have several source points with intervals but **no selected point and no visible original interval**; active-report choice can cause the current marker to be unmatched. Do not assume adding a toggle alone fixes this.
- `client/src/components/LabReportOverlayControls.tsx` has report activation and provider controls inside `LabReportOverlayPanel`'s collapsed `<details aria-label='Report reference overlay preferences'>`; this works for advanced report setup but is not a suitable required path for routine viewing.
- `LabRangeSelector` already supplies provider, province and collection-context inputs; `LabTrend` currently mounts only `contextOnly` and only after a provider is already selected. Implement a compact chart-facing selector that reuses existing service/state rather than embedding a second overlay controller.
- `scripts/qa/report-range-overlay-journey.mjs` covers synthetic source-reference invariants and the old manual workflow. Adapt tests to the **new user-visible chart journey** rather than merely a fixed historical heading; preserve all real safety assertions.

## Required interaction / source selection state
1. **Default display:** when a marker has available compatible source points, choose a deterministic **latest eligible recorded observation for chart context** (with an explicit accessible label and date), subject to actual owner/report/revision/identity; default a usable source interval for that observation if available. If the latest point is not usable but an earlier point is, **do not silently present the earlier interval as the latest**: either show latest with “No reference range was provided with this result” and offer the prior recorded point, or explicitly identify that an earlier dated point was selected; choose behavior that best maintains user-visible truth. If multiple points share timestamp, do not silently choose an arbitrary one as definitive: preserve occurrence selection and explain ambiguity.
2. **Original report first:** no provider confirmation or report activation required merely to display an *already recorded* and source-compatible original interval. Resolved plotted interval is either verified shared across all compatible report observations, **or selected-result-scoped and visually localized**; never a band across incompatible reports/methods/dates. One-sided upper/lower stays one-sided. Where units or assay identity fail, show source-only and reason, not a fake range.
3. **Visible chart control:** place adjacent to chart (above preferred): `Show reference range` (default ON for applicable unsuppressed original; checked state reflects actual display) plus `Reference source` with `Original report`, `Published comparison` (only if a relevant provider option is supported), `None`. The toggle and source choice must not conflict; off must be represented as/behave like `None` in the existing overlay model, with a predictable way back to original or the last permitted published choice.
4. **Persistence rule:** any explicit saved **None** remains authoritative after reload. A user's saved report preference and source-scoped record/confirmations take precedence over defaulting; missing saved preference should use original-report default without writing to clinical records. State updates shown immediately and sourced through existing `useLabReportOverlays` mechanisms. Distinguish session-only selection vs persistently saved report preference. If `reportKey` genuinely absent, provide session-only original display using the selected source point with no invented report association; no cross-report preference propagation.
5. **Published comparison within chart:** rehost or reuse `LabRangeSelector` with focused provider and province options beside chart; context subpanel collapsed unless needed for relevant choice. Show provider, jurisdiction, date, citation and provisional status, distinguish reference interval vs clinical decision limit vs threshold; avoid implying performing laboratory identity. Existing source-specific confirmation/revision invalidation and no unknown-age/specimen inference remain mandatory. **Original source precedence remains:** do not replace an applicable original interval with an external comparison, even when user chooses the latter; make explanatory label clear.
6. **Clear no-data states:** if selected result has no original interval, say **“No reference range was provided with this result.”** If bound is present but unsupported/incompatible, explain the actual reason instead of “not supplied.” If selected report has no current occurrence of marker, keep the truthful source message and offer a current observation, not range borrowing. All options are labelled, not color-only; avoid green/red clinical verdicts.
7. **Advanced management:** retain `LabReportOverlayPanel`, original report/source and data correction, reviewed collection demographics, report matching, saved preferences and provenance behind a clear `Manage report and reference sources` disclosure/link. These controls are not prerequisites for original range display.

## Owner extension — Intelligent Canadian selection and user-corrected laboratory ranges (2026-11-16)

**This is an amendment to the SAME P1 chart-first implementation, not a second workstream.** The product owner wants a true, context-supported Canadian reference fallback when the actual report lacks a usable interval, plus a simple **Use my laboratory's range** correction beside the chart. Implement the fast, valuable original-range/correction UX first, then incrementally add verified Canadian comparisons; **do not block the first slice pending national reference table ingestion**. No new lab reference engine, provider store, AI clinical score, chart component fork, or serial approval cycle.

### Required deterministic selection and labels
1. The **owned observation's original source-specific interval** is preferred if compatible and not explicitly disabled. A previously saved, source-specific **user correction copied from the actual lab report** takes precedence over an outdated/incorrect imported interval, but remains a distinct user-confirmed correction; it must not mutate the immutable original. Preserve explicit saved **None** and existing choices over a fresh default.
2. If no original/corrected applicable interval exists, evaluate the **existing** `shared/lab-provider-ranges.ts` catalogue and extend its source/type/version schema only where genuinely needed. Candidate order: (a) verified exact performing-laboratory, assay, specimen, age/sex-at-collection and era match; (b) applicable verified **CSCC harmonized** interval; (c) relevant provincial/other Canadian published reference as a clearly identified **provisional comparison**; otherwise unavailable/ambiguous. These are source classes, **not permission to assume that current catalogue already contains a valid source**. A source with no non-null bound, missing rights, unverified applicability or only geographic similarity cannot become a confirmed match.
3. Use exact canonical analyte and **verified** LOINC where actually available; confirm clinically relevant subtype, source specimen, assay/method, compatible units/UCUM conversion, collection date and effective period, laboratory, province, age at collection (only from valid historical context), reference-population category and fasting where required. Unknown fields stay unknown. Never infer a lab from geography, or draw on current profile demographics for an old report without a validated historical basis. Do not assume every candidate must specify the same fields: match its stated applicability requirements explicitly.
4. **Never select ranges according to whether measured value appears normal.** Use value/flag only for separately labelled data-integrity checks: original flag/interval/value consistency, questionable unit/interval transcription, and high-priority review where plausible candidates classify differently. Two plausible materially distinct candidates produce **Multiple plausible comparisons** and do not silently resolve in favor of an in-range result. Deterministic source match reasons and abstentions, **no fabricated numerical confidence score**.
5. Every chart must clearly identify one of: **Original report confirmed; User-confirmed laboratory correction; Verified laboratory-specific published comparison; Canadian harmonized comparison; Provisional published comparison; Multiple plausible comparisons; Reference unavailable**. Published material is **never** relabelled original and decision/risk limits stay separate from normal reference bands. Present concise source/date/version and eligibility caveat beside band or one-sided line, with full citation and method/population limitations on drill-in.

### Confirmed source implementation (2026-11-16)

This drops all connections when a single pair lacks complete lab/method/fasting information. `assessLabComparability` in `shared/lab-comparability.ts` currently returns explicit reasons such as `laboratory-unknown`, `laboratory-changed`, `method-unknown`, `method-changed`, `fasting-unknown`, `fasting-changed`, `units-differ`, `assay-identity`, `duplicate-time`, `invalid-observation`. ### Required pairwise visualization
- Introduce one **small deterministic, pure display-only classifier** that consumes a marker ID and **two adjacent valid chronological observations**, reuses `assessLabComparability(marker,[left,right])` reasons and returns `solid | dashed | disconnected` plus enumerated human-readable reasons. **Never set scientific comparable=true because a segment is drawn.** Shared `assessLabComparability`, source comparability eligibility, `t.comparable`, strict selected-point numerical difference and AI/clinical claims must remain unchanged.
- **Solid:** two confirmed same-analyte/assay, compatible canonical units and sufficient laboratory/method/fasting/source comparability (pair-specific `assessLabComparability(...).comparable`).
- **Dashed:** same **confirmed marker and assay subtype**, finite same-unit or explicitly valid converted numeric values, **valid and strictly increasing timestamps**, but only *nonfatal source context* differs or is unknown (laboratory, method and fasting when relevant). Include which reason(s) affected the pair. No clinical equivalence inference.
- **Disconnected:** any invalid numeric/date/plot unit, unverified/conflicting analyte or assay subtype, lack of verified conversion/common comparable numeric unit, same/unordered timestamp, or any other potentially unsafe/unclassified reason. If later classifications introduce a new reason, **default to disconnected**, not dashed. Mixed raw original units must be handled by verified canonical conversions, not inferred from visual proximity. Source-linked original data stays unchanged.
- **Segment-local:** sort a **display-only** working copy chronologically by actual full timestamp and stable tie handling; classify adjacent pairs independently, render each segment with separate SVG line/path (not one whole-series polyline). Do **not** join across invalid, duplicate-time, superseded or source-withdrawn points; don't skip a point to bridge a gap. Duplicates remain separately selectable but have no asserted order or connection through that occurrence. Avoid fabricated interpolation, smoothing that implies values between observations, or uniform spacing; preserve actual x distances and individual data points.
- Use existing CSS/Tokens: `bvc-recorded-series` solid, new restrained dashed stroke variant; clear endpoints, accessible non-color legend (only entries actually represented), helpful contextual explanation of segment cause on keyboard/touch selection via accessible list/buttons or descriptive chart text, visible reason for disconnected adjacent pairs. Correct SVG `<desc>` currently says all points unconnected when `t.comparable=false`; update to summarize actual segment states. Data labels, point selection/source actions and dates remain truthful.
- **Do not conflate this with reference-range selection:** a dashed or solid segment does not cause two different labs' original intervals to become a shared historical band. Source range applicability and previously saved explicit None / user-corrected interval / Canadian provisional comparisons remain separately computed from the same source evidence. No range-based normalization of plotted lines.
