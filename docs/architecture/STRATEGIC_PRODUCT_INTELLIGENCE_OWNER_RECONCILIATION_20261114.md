## Binding engineering slices — shortest useful path

### P0-A — Today→Food concrete meal journey (extend Issue #12; not another engine)
**Reuse:** `shared/wellness-actions.ts` reviewed action IDs, `shared/goal-guidance.ts`, `shared/meal-intelligence.ts`, `shared/nutrition-summary.ts`, `shared/food-preference-policy.ts`, existing meal source/portion review in `LogMeal.tsx` and `MealAnalysis.tsx`, `PlanDay.tsx`, `TodayFocus.tsx` and wellness intent/receipts in `WellnessChoiceDetails.tsx`.

1. Freeze a user's minimum owned `date, goals+priorities, allergies/exclusions, preferences, recorded available meal nutrients+coverage, time/budget/effort if known, source+revision/evidence version` context; permit sparse context and unknown values. Do not infer unlogged nutrient deficit from a subtotal.
2. Generate a small set of real **approved food/meal candidate IDs with ingredient/quantity/source anchors** (curated safe recipes or actual source-matched saved foods where applicable), not fabricated restaurant products. Apply food safety, consent, dietary exclusions, limits/contraindications **before** ranking. Choose goal-relevant practical options with deterministic, transparent scoring/tie-breakers and explicit material conflicts; never claim individual optimum.
3. First acceptance fixture: breakfast/lunch recorded with *some* known energy/protein/fibre source values → propose a dinner with real specified portions that improves a material *known opportunity* (not diagnose deficiency), with a reasonable alternative and why this is feasible. Also test no-food day, partial/unknown nutrient fields, unknown time/budget and ingredient excluded by preference.
4. Candidate flows straight to an **editable prefilled existing meal review**; user can change ingredient/portion/servings, substitute with explicitly calculated `before/after known source contribution`, save later or plan; logging eaten must require separate confirmed consumed action. Reuse idempotent source checks, Review/Save flow, no phantom diary row.
5. Render **one usable primary Today action** with named meal/portion/time and reason, not `log something` process prompt. Source/correction/eligibility issues cause safe general specific alternative, not a blank screen. Avoid per-user perfection gates.
6. In same slice fix the known servings `Number('') -> 0` edit defect and numerical draft/cursor regression (#12). Typecheck and source/meal test coverage first, app/browser/DB second, frozen-SHA visual third. No new DB or paid AI service.
7. Integrate with isolated feature branches #13/#14 through controlled PRs: their design files are **reference-only or non-app commits**, so runtime UX work should not wait for an allegedly delivered refactor; rebase/review conflicts before merge.
