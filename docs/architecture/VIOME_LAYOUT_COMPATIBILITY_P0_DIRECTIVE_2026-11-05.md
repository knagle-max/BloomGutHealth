## 2. Mandatory coordinate-aware architecture

1. **Page geometry:** Reconstruct layout from PDF.js text items with coordinates and font/scale when available, normalizing item transforms and page rotation. Detect primary provider/template kind, section title, subheading, table boundaries, header/footer, legends, prose blocks and repeated title/section markers. Section state is a **document-level finite-state machine**, carried across pages unless a verified heading changes it, rather than a by-column incidental last category. Do not make page number alone determine type or section.
2. **Row reconstruction:** Cluster fragments by bounding-box overlap and adaptable font-relative y tolerance (not an absolute 3px), sort visually per actual table/column, detect variable column bands and repeated paired subcolumns, then assign name to classification/category by visual row proximity plus admissible table context. Handle up to three simultaneous name/category pairs per food row, uneven column widths, long names/punctuation/preparation and fragments splitting one word or suffix. Avoid cross-column category bleed. Maintain source page/column/row indices and parse confidence/ambiguity per row.
3. **Organisms:** Retain complete verbatim scientific name and original provider class (Bacterium/Bacteria, Virus/Viruses, Eukaryote/Eukaryotes as allowed mapping), preserving strain suffixes `Bacteroides thetaiotaomicron VPI-5482`, `Bifidobacterium pseudocatenulatum`, `Bacteroides fragilis 638R`, `Bacteroides fragilis YCH46`, `Bacteroides sp. CACC 737`. Use `reported_present`; NEVER infer abundance, relative concentration, toxin, functional activity, pathogenicity or absence of non-listed taxon.
4. **Assessments:** Pair each exact health-score name to its neighboring visual category `Maintain`, `Improve`, or `Attention`, while filtering explanations/legends from data. Preserve ordinal provider context only; no invented 0–100 score or measured metabolite concentration. An actual explicit numeric source result is a distinct field only if supported by existing schema and separately verified.
5. **Foods:** Parse visual table of three concurrent pairs, keep exact food name and original `Superfood`/`Enjoy`/`Minimize`/`Avoid`, qualifier/preparation and source location. Include `Almond Milk (Unsweetened)`, `Bone Broth (Poultry)`, and `Egg Whites (Chicken or Duck)`. Provider advice does not become a mandatory Bloom restriction, allergy or independent scientific recommendation. Do not substitute a generic food synonym for the exact source string.
6. **Metadata:** Only allowlisted provider/test/specimen/method and valid collected/received/reported dates, each correctly distinguished. **Do not read, retain, match on, compare, parse into model, or log demographic, client/patient, DOB, name, sample, test, kit or order identifiers, original PDF bytes or raw full text.** The user explicitly directed no captured/stored identifiers. Thus the user-provided inconsistency between synthetic companion demographics must NOT be used to match/merge reports; same sample IDs must likewise not be used. Related report linking is via authenticated user-selected pairing with compatible non-identifying dates/specimen/report kind and user confirmation; ambiguity leaves files separate. No DOB/PDF-created/upload date substitution for biological collection date.
7. **Two-phase extraction:** Return an allowlisted `ViomePdfDraft` with successfully recognized entries, field-level error flags, bounded page/column/row references and row-specific `needs_review` states; **never write permanent data during extraction**. Existing review screen supports correction, source position, explicit confirm, one atomic owner-bound save and reload. Ambiguous rows cannot silently pass the accepted schema. A report with some reliable findings is marked `PARTIAL_REVIEW_REQUIRED`, not `complete`; block save as complete until user resolves required fields or explicitly confirms a supported partial-data state, with accurate counts and no unknown-as-zero. Structural uncertainty rendering data unreliable => fail safely. Errors must not contain raw text/PII.
8. **Boundaries:** Existing PDF.js, `shared/viome-pdf.ts`, `shared/viome-findings.ts`, adapter routes, report review, immutable source/correction/re-import and tenant isolation remain authoritative. Keep resource/abort limits and never send a whole raw PDF to external AI/OCR. Extend existing draft schema only with justified bounded review flags, not extra persistence of raw identifying spans.
