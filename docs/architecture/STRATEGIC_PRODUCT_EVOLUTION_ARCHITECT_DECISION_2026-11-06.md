## 1. Binding strategy: one understandable, actionable, permission-controlled wellness product

**Approve the common direction:** “Understand what is known → choose a feasible, evidence-reviewed action → log/observe → cautiously reassess.” Data-rich nutrition, bloodwork, genetics, microbiome, activity, goals and optional recovery should cooperate without an optional assay/device/paid model being mandatory. A useful **goals-only** baseline is the first proof of value. Primary experience is NOT an LLM chat, an autonomous doctor, health-grade scoreboard or novel personal treatment predictor.

**Branding positioning:** Retain **Bloom**, approved visual assets/tokens and Everyday green/Athlete navy-blue distinction, with existing Today / Explore / Progress navigation and normal Food/Move/My Biology/Settings routes. Approve proposed future-facing category headline **“Make sense of your wellness.”** with supporting accurate, nonclinical copy, **subject to Legal claim/actual feature parity before publishing**; do not replace brand identity or imply connected wearable, health data integration or improved outcomes if feature isn't working. Proposed “Start with a goal” onboarding and source-optional messaging belong to v0.6 user-value work, not a v0.5 redesign.

**Architect emphasis:** Useful personalization = verified goals, preferences, available time, food restrictions, genuine logs, comparable measurements and approved general guidance. Genotype/microbiome research may help explain a topic, but a source observation is not proof of individual response. We must **not blanket-gate source-backed educational findings** behind a clinical-claim approval; only consequential individual effect, treatment, diagnosis and intervention claims require the corresponding stronger evidence/authority. This preserves the prior Genetics source-education and functional microbiome architecture corrections.

## 2. Distinct domains and single reused architecture

**Single unified flow; no second engine:**
`canonical owned source+revision+consent records` → **read-only scoped/time-aware context** → **existing reviewed evidence/approved action registry** → **eligibility/safety veto** → **deterministic, explainable ranking of allowed action IDs** → **versioned recommendation explanation/snapshot** → current Today/Goal plan/Athlete/Progress screens → user-controlled act/skip/change → **observed, not causal** progress and recalculation. Existing food journal and workout sets/rep/load stay canonical; no new activity or report store.

Five important separations:
1. **Eligibility before ranking**: restrictions, allergies, medically sensitive flags, conflicting source methods, consent, unavailable evidence and time/feasibility veto ineligible actions. Ranking can prioritize goal relevance and cost/time within the approved set; cannot reinstate an ineligible action.
2. **General action vs individual claim**: Biology's `general_wellness`, `context_personalized`, `exploratory_education`, `withheld_or_refer`, and unavailable `clinically_governed` classifications. Guideline evidence for an action is not proof that genetics, microbes or a lab value predict a person's treatment response. The personal data input may explain *why the topic matters*, not causal attribution.
3. **Source data vs inferred**: preserve actual measured vs self-reported vs calculated vs provider categorical vs reviewed research vs unknown, including source date/assay, unit, completeness and any revision. No unknown-to-zero, qualitative taxon-to-butyrate output, genetics-to-diet dosage, wearable stage-to-diagnosis, or incompatible lab trend.
4. **Privacy/purpose**: one user permissioned context materializer; individualized outputs cannot leak across users, coach/public data or external AI. Deletion, correction, source choice, opt-out, evidence withdrawal and account switch invalidate derived recommendations. Report-food opt-in remains a separate default-Off source-ranking permission, not external-model sharing consent.
5. **Deterministic first/AI optional**: all core actions, source explanations and fallbacks must function with no LLM or paid account; any optional model drafts only over minimized, allowlisted approved facts, with no eligibility/action authority, no novel medical effect claims, no independent tools or silent writes. Paid activation retains existing tariff/budget/unknown-charge reconciliation gates. No mandatory vector database, proprietary cloud model, graph DB, GPU or new consumer score.

**Data model policy:** Reuse current source IDs, existing action IDs/evidence registry, normalized observations, goal constraints, consent records, snapshot receipts and SQL/Postgres for source/version joins. Extend typed interfaces only for a reproducible multi-domain read context, eligible-action decisions, reasons and observed follow-up; avoid a fresh universal schema or unjustified migrations.

## 4. Developer-ready v0.6 sequence, with exact exits and no v0.5 interruption

**Phase 0: v0.5 current branch reality check (no new plan project).** Codex continues current `NEXT_ACTIONS.md` actual uncompleted tasks: report source deletion/linking and category-wide controls as scheduled, native Viome exact private acceptance, remaining demonstrated UI/safety defects, engineering vs independent release status. Do not reopen already passing work from old handoff or rerun unchanged full suites. After actionable v0.5 slices are delivered or narrowly classified as independent external acceptance, move to Phase 1, without pretending outstanding real-device/legal/security gates passed.

**Phase 1: bounded read-only context + source/consent/evidence contract.** Inventory actual existing `SCIENCE_COACH`, `PRECISION_NUTRITION`, action registry and Today/Plan/Athlete routes, plus latest code SHA. Build/extend one read-only typed permission/temporal/materialized context. Account isolation, missing data, source revisions, conflict/method/version and deletion invalidation tested. Reuse existing schema with minimal migration, if any. Integrations' approved modular-monolith dependency audit runs **bounded and concurrently**, not as an open-ended rewrite. **Exit:** context and approved rule IDs resolve from goals-only and from corrected full-source test accounts, showing clear unknown/missing, with no extra provider/API requirement.

**Phase 2: first full working value loop — no AI.** Expose a reviewed low-risk action family through **existing Today**, with one main actionable card `What you can try`, real `Why this?`, effort/feasibility, `Try / Save for later / Not relevant`; reroute to existing Food/Athlete/manual actions, record actual user choice without claiming it completed. Add 2–3 approved families (for example dietary substitution, gradual fibre food option, easy movement session), safety exclusion/cross-domain conflicts and goals-only fallback. Extend same eligible selection to existing Eat–Move–Recover planner, **without building another planner**. **Exit:** uncoached simulated account can select goal → obtain feasible cited action → act/log/edit → reload → see correct status/why and optional follow-up even with every optional source and AI provider disconnected.

**Phase 3: observed progress and reassessment.** Existing Progress shows comparable source-dated outcomes, actual completion/adherence only if entered, missingness, method noise and optional check-in/reflection; recompute when source/consent/evidence version changes. Don't infer effect of intervention from association. **Exit:** change one source input and observe deterministic reranking or meaningful abstention; support no valid outcome, skipped action and contradictory sources without false achievements or stale outputs.

**Phase 4: progressive refinements.** Expand eligible action families, simple accessible goal pathway, source-control hub, Athlete cross-domain relevance, remaining UX and consent surfaces; first-party brand copy continuity only when claims match running code; optional sleep/manual tracking. Monitor concrete error/support/outcome and usability evidence, no pressure-driven engagement.

**Phase 5: later research and separate gates.** Only if baseline proves useful, study low-risk experiments, adaptive suggestions, enriched microbial/gene education, optional LLM phrasing and retrieval, learned rankers, connected wearable, Coach or more clinical functionality under earlier individual priorities and qualified approval. No “whole body twin” implementation mandate for v0.6.

**Engineering checkpoints:** Every phase reports current tested commit/CI/deployed SHA, actual code reused, synthetic fixtures and negative cases, source/evidence versions and permission tests; independent User Testing/Science/Security/Legal/Branding states separate. **Do not require all 15 UT-EVOL, all 12 Biology action families or all 8 ML-STRAT workstreams to be finished before the first meaningful v0.6 release slice.** Each tranche must produce observable working user value.

## 5. Unified minimum contracts — extend, do not duplicate
`WellnessContext`: `accountScope, purpose, selectedGoals, constraints, explicitPreferences, observations[] {sourceId,sourceRevision,kind,method,unit,observedAt,collectionDate,quality,coverage,consentScope}, missing[], conflicts[], evidenceVersion`. No raw private files or identical duplicate payload copies.

`ApprovedAction`: `actionId,version,category,goalApplicability,requiredInputs,contraindications,restrictions,evidenceClaimIds,permittedOutputClass,effort,estimatedTime,reviewedStatus`.

`ActionDecision`: `eligible:boolean,reasonCode,contributingSourceVersions[],reviewedActionVersion,evidenceVersion,why,uncertainties,alternatives,consentVersion`, with source-linked but **privacy-safe** materialized reason text. Versioned candidate ID, not a generated freeform health prescription.

`ActionObservation`: `chosen|deferred|dismissed|performed_if_confirmed,recordedAt,actionVersion,existingJournalOrWorkoutRef?,userFeedback?,comparabilityContext?`. “Try” is intent, not adherence. User's actual logged completion is authoritative.

Mandatory states: `no_data`, `incomplete`, `stale`, `conflicting`, `withdrawn`, `no_permission`, `not_eligible`, `review_only`, `provider_unavailable`. Not equal to numerical zeros or a single false-confidence score. Add explicit data source/algorithm provenance and authorization to outputs.

## 6. Acceptance, specialist ownership and activation rules

**Biology:** publish reviewed specific action-family claims, eligibility criteria, contraindications and outcomes/measurement applicability. Separate Grade A general intervention from insufficient biomarker/genotype/microbiome *personal modifier* evidence. Science review is **claim-specific**: no blanket approval delay to display measured facts or established general education.

**AI/ML:** deterministic candidate filtering and auditable relative ordering, null/unknown and dedup logic, clear why/why not, no provider-model authority for new actions. Before any advanced ML/LLM launch supply frozen baseline/challenger, out-of-sample relevant efficacy/task utility and error cost; synthetic examples alone not efficacy validation. No routine paid calls or hidden liabilities.

**Brand/UX:** existing brand/modes, optional goal-first onboarding, meaning-first action card, consistent source status, respectful autonomy. Exact live UI artifacts at relevant widths and screen reader. Branding sample headline is **provisional until commercial copy reviewed**.

**User Testing:** compare at least goals-only, rich data, contradictory/missing and consent-off flows; run independent 5–8 participant formative study and appropriately sized confirmatory evaluation. Specified metrics (uncoached task completion, 5-minute first action, suggestion relevance, misconception/error, time to log, source navigability) are **proposed targets not measured product performance**. Retention comparisons require defined denominators and actual longitudinal outcomes, not notification open rates.

**Security/Legal/Integrations:** verify exact scope and deletion of data, purpose-limited consent and AI transmission, source rights, intended use, acceptable cross-border flows, original provider semantics/algorithm version, manual/device dedup and managed audit/retention. No material new paid supplier, external transfer, clinical service or destructive production operation automatically authorized by strategic planning.

**Owner decisions:** No routine new approval is necessary to build within above approved v0.6 staged scope, but paid/clinical/irreversible/sensitive-sharing activation still explicitly gated.
