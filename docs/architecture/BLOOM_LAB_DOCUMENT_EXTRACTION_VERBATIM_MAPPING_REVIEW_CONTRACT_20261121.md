## 1. Required schema contract in `shared/lab-extraction.ts`

Implement **runtime Zod validation** and inferred TS types for the user's proposed enum names and three-stage record classes, with backwards-compatible additions below. Pure shared schemas only; no provider/network/secret or document bytes in the shared module. Unknown/inconsistent fields rejected.

### Owner-specified stable enums

```ts
type LabExtractionMethod = 'manual' | 'local-ocr' | 'local-vlm' | 'cloud-vlm-redacted';
type LabResultKind = 'numeric' | 'censored' | 'qualitative' | 'unparsed';
type LabAnomalyFlag =
  | 'calculated_vs_measured_ambiguity' | 'multiple_specimen_dates'
  | 'duplicate_row_in_document' | 'stratified_reference_interval'
  | 'censored_operator_present' | 'qualitative_result'
  | 'unrecognized_unit' | 'unmapped_analyte'
  | 'supersedes_prior_report' | 'redaction_incomplete';
```

Preserve owner field names below while adding `version:1`, strict bounds and necessary `mappingStatus`/audit fields:
- `LabSourceDocumentRecord`: `documentId`, authenticated internal `accountId` (never trusted from client), `sha256` of original *bytes* under encrypted private control, `uploadedAt`, `retentionPolicy.storageMode:'ephemeral_memory_only'|'encrypted_ttl'`, `expiresAt`, `deletedAt`, `redactionApplied`, `redactionVerified`; `extractionProvenance` containing method/provider/model/version/consent revision; `performingLabPrinted`, `reportIssuedDatePrinted`, `isAmendedReport`. **Avoid exposing a raw public SHA-256 of a sensitive/small/known PDF**: only encrypted account-private storage; external/shared receipt use a domain-separated keyed HMAC or opaque ID. A hash does not recreate a deleted original PDF and cannot prove a later edit from a now-purged document; after purge show retained *printed source text* and explicitly indicate original-image verification unavailable.
- `RawLabRowCandidate`: source `rowId`, **1-based** page number and normalized bounding box `[x,y,w,h]` bounded to [0,1] with `x+w<=1,y+h<=1` and defined page orientation/crop rotation. Preserve literal `panelHeaderPrinted`, `analyteNamePrinted`, `valuePrinted`, `unitPrinted`, `referenceIntervalPrinted`, `labAbnormalFlagPrinted`, `specimenCollectedAtPrinted`, `specimenTypePrinted`, `methodologyPrinted`. `advisoryConfidence` [0,1] **is never acceptance evidence**. Add **per-field confidence/uncertainty** including source bounding boxes where feasible; a single row score cannot tell whether the wrong decimal/date/unit was OCR'd. Use explicit `not_detected` state rather than treating missing field as empty normalized value.
- `MappedLabRowCandidate` extends raw with `canonicalAnalyteCode|null`, `canonicalAnalyteLabel|null`, `resultKind`, `parsedNumericValue|null`, `relationalOperator:'='|'<'|'<='|'>'|'>='|null`, `qualitativeValue|null`, `ucumUnit|null`, `normalizedValue|null`, `normalizedUnit|null`, `specimenCollectedAtIso|null`, `flags:LabAnomalyFlag[]`, `supersedesRecordId|null`, `reviewStatus:'needs_attention'|'ready_for_confirmation'|'excluded'`; **add** `mappingBasis` with canonical registry version, source label+specimen+method match, unit conversion rule ID, matching confidence as *deterministic status* `exact|ambiguous|unmapped`, and `timePrecision` to separate printed date-only from real timestamp. A generic LOINC-aligned code does not imply a fully verified LOINC entry; use actual permitted codes only when independently mapped. Return explicit `not-computation-eligible` for censored/qualitative/unrecognized/incompatible values.
- `ConfirmedLabImportPayload`: owner-specified `documentId`, `documentSha256`, `confirmedAt`, `confirmedByAccountId`, `deleteOriginalFileImmediately:true` default and `rows[]` with original printed provenance. **Server sets** confirmedAt/from authenticated session and performs document account binding; client-supplied IDs/time must never confer authorization. Add `extractionReceiptRevision`, expected account source revision, document revision, idempotency key and explicit row decisions `confirm|correct|exclude|save-source-only`. The exact confirmed canonical payload is created server-side after comparison with current validated candidate and original document; do not trust changed client `normalizedValue` or `canonicalAnalyteCode` without re-derivation and explicit review. `ucumUnit` required only when genuinely mapped numeric result; **do not require it** for a source-only qualitative or censored row. Preserve all supported source-only entries without fabricated timestamps, units or numbers.

### Conversion/eligibility contract (critical)

| Printed result | Candidate parsing | Destination and computation eligibility |
|---|---|---|
| `4.82` with recognizable unit, verified analyte/assay/date | `numeric`, `=`, numeric 4.82 | Existing `labSchema` **only** if confirmed, unit/date/method/applicability qualify; otherwise `sourceOnlyLabSchema`. |
| `< 0.60`, `> 90`, `<= 5` | `censored`, preserve threshold and operator | **Source-only** until an explicit versioned bounded-result type/reader/calculation policy is approved. Never coerce threshold as measured value, use in a line plot, or compute ratios/changes from it. |
| `Negative`, `Reactive`, `Trace` | `qualitative` verbatim | **Source-only** unless separately supported analyte-specific qualitative source/interpretation version exists; no numeric zero. |
| `4,82` | keep exact printed text; decimal comma parse only when report locale/format unambiguous | Ambiguity -> human review; record parse rule and source. |
| `LDL-C (Calculated)` vs `LDL-C (Direct)` | distinguish method and registry identity | Separate **assay/method identities**, not necessarily two existing `marker` enum members. Same high-level display category may remain but comparability MUST refuse inappropriate merging. Add alias/identity only via reviewed catalogue and old-series regression tests. |
| Missing/ambiguous collection date, reference interval or unit | preserve source strings and flags | **Do not manufacture `measuredAt`**, midnight as real time, or reference bounds. Request user-confirmed date precision; save a report-only pending candidate if unresolved. |

**Reference intervals:** often stratum-specific, closed/open boundaries, qualitative, textual and method-defined. Store `referenceIntervalPrinted` exactly. Numeric `referenceLow/High` only if cleanly and applicable to source conditions; otherwise preserve text and `stratified_reference_interval` flag, never choose an arbitrary sex/age interval.

## 2. Runtime Stage A / Stage B / Stage C

**Stage A — verbatim extraction, untrusted:**
1. Accept locally authorized PDF/JPEG/PNG under strict MIME/magic check, size/page/pixel/decompression/time quotas; reject damaged, encrypted, malicious or unsupported documents safely. No scripts/macros/network URLs.
2. By default use manual entry or approved local OCR/VLM where genuinely available. Build deterministic synthetic fixtures before enabling any model. For cloud request, require separate `lab-document-extraction` purpose, provider/version/endpoint/billing/retention authorization, source rights/territory and bounded `MeteredAIExecutor`-integrated spend controls **after** registered feature/policy review. Do not add `lab-document-extraction` as an enabled feature by changing only an enum. `store:false` is only one applicable provider option; assess logs/abuse monitoring and paid project policy.
3. Scrub identity fields **before** model transmission. Client-only masking may fail in scans, headers/footers, QR codes, side notes, filenames, image metadata, accession numbers or barcodes. **Fail closed** on any unverified identity region or uncertain redaction, even if explicit consent was given. But lab site, collection date, sex/age-specific reference text, specimen and assay may themselves be sensitive; absence of name does not prove anonymity. Never assume cloud-safe merely by successful OCR redaction; require independent privacy and provider-use review. Allow no-cloud fallback.
4. Keep candidate response separate from authoritative record and verify model output schema/limits. Do not show fabricated bounding boxes as real document citations; if OCR cannot anchor a field, mark location unavailable and demand review.

**Stage B — deterministic mapping and comparison:**
1. Read report date and specimen collection date separately. Recognize dates, relative-time ambiguity, local time zones/DST and specimen-level variation. Mark issued date vs collected date explicitly; don't silently substitute issue date for measurement.
2. Parse verbatim strings into units/operators/qualitative/censored flags **without editing raw**. Match exact analyte, specimen, calculation/methodology and performed lab via reviewed Bloom registry; preserve ambiguous matches and known-incompatible assay identities. Normalize only with versioned, tested source-unit conversion rules, not prompt output.
3. Deduplicate repeated page/column/row *within one document* by source position/identity and actual specimen, but don't drop biologically distinct repeats (multiple specimens/timepoints) or serial fasting values.
4. If document says amended/corrected, identify candidate links against **same account** old imported record and source revision; user verifies. `supersedesRecordId` is a proposed relation, not permission to mutate/delete old data.

**Stage C — side-by-side human review and commit:**
1. Render clear side-by-side thumbnail/crop with page and row highlights; prioritize low per-field confidence, absent boxes, unknown units, specimen ambiguity, nonnumeric/qualitative/censored values, calculated/direct ambiguity, corrected reports, duplicate rows, discordant intervals and redaction warnings. **All** rows explicitly accepted, corrected, excluded or preserved source-only; 0.99 confidence cannot bypass review.
2. Offer a clear correction path that edits the **printed candidate** and forces mapping recomputation, not silent overrides of normalized numeric field.
3. Before commit, server re-read authenticated ephemeral document/candidate, verify expected revision, source identity, existing match set, ownership, explicit row decisions and idempotency; use current `insertReviewedLab` for each **validated** eligible row or narrow transaction-aware batch adapter. If a multirow batch cannot be atomic under existing storage, do not pretend atomic; use resumable per-row receipts with idempotency and explicit partial status instead of hidden partial saves.
4. Confirmed records retain minimized source-row provenance; source-only censored/qualitative observations remain visible but ineligible for unsupported analysis. Run actual source-epoch/cache invalidation after new import or correction.
5. Trigger immediate best-effort encrypted temporary file purge **after verified durable commit** when deletion chosen. TTL enforced by cleanup independently of the request, including crashes, expired sessions, draft abandonment and provider failures. Document whether residual backups/provider retention are included; do not claim cryptographic deletion if unproven. Consent withdrawal must block future external extraction and delete staged drafts according to policy without deleting already legitimately saved clinical facts unless user separately requests.
6. No storage of original crop thumbnails in browser caches, analytics, public logs or provider request receipts; preview access is account-scoped/short-lived, cache-control `no-store`; on logout/account switch wipe preview state. If source PDF purged, communicate that review crops are no longer available.

## 3. Required negative/acceptance tests

- `LAB-X-01` Exact OCR preservation: spaces, inequalities, unicode unit symbols, decimal commas, flags, panel headers, repeated rows, specimen date vs issued date.
- `LAB-X-02` Fake confidence 0.99 with a shifted decimal, wrong unit or wrong crop remains untrusted and requires explicit human review; mapping corrects after confirmed printed edit.
- `LAB-X-03` Censored `<0.60`/`>90`, qualitative `Negative`, `Trace` and unparsed rows do **not** become numeric 0.60, 90, 0, or fabricated `measuredAt` and cannot change biological numeric conclusions.
- `LAB-X-04` LDL calculated vs direct, PSA total vs free, vitamin D isoforms, ambiguous assay/method and incompatible specimens; series and comparisons remain safe.
- `LAB-X-05` Multiple specimen dates, time zone, date-only, time precision, mismatched issued/collected date, stratified reference and corrected report.
- `LAB-X-06` PDF with identifiers in body/headers/QR/metadata/cropped text, uncertain redaction -> cloud fail closed, **zero** external call including retry/telemetry; local/manual still works.
- `LAB-X-07` User A cannot view, import, link superseding record or retrieve preview of user B; confirmedByAccountId is server-authoritative; no arbitrary record ids.
- `LAB-X-08` Corrected same-specimen report links existing record only after review, retains old audit/source revisions, prevents duplicate active lab measurement and invalidates only dependent interpretations.
- `LAB-X-09` Multirow 1–100 page fixture, mixed valid and source-only entries, save replay/idempotency, crash halfway, stale review match set, page duplication and retry, with no silent partial success or duplicate import.
- `LAB-X-10` Original PDF/image encrypted or memory-only, clean TTL job after 24 h if configured, explicit early purge after verified save, expired preview inaccessible, account switch/logout/erasure cleanup; backup residual disclosed.
- `LAB-X-11` Extraction output schema prompt injection, absurd file/page/bounding box/confidence, unsupported content, decompression bomb, invalid redaction and model failure safely rejected.
- `LAB-X-12` No-cloud manual/local path has no provider calls or spend; cloud OFF/consent revoked/provider 429/timeout/budget exhaustion uses local/manual fallback with no duplicate billing; actual policy and provider terms separately reviewed.
- `LAB-X-13` Historical records and chart/Response remain unchanged after adding v2 extraction capture metadata; migrated new records preserve source-page/row audit and versions through export, corrections and account erasure.
- `LAB-X-14` Blind previously unseen multi-page fixture with numeric/censored/qualitative, conflicting/duplicate LDL, amended record and ambiguous collection dates; measure extraction and mapping error **per field**, human correction burden, save accuracy and no fabricated facts. Compare against manual-entry baseline. Keep original fixture/answer hidden until code/version frozen.

**Exit states:** `SPECIFIED`, `CODED`, `SYNTHETIC_TEST_PASS`, `LOCAL_FILE_TEST_PASS`, `PROVIDER_POLICY_APPROVED`, `HOSTED_PRIVACY_VERIFIED`, `INDEPENDENT_SECURITY_REVIEWED`, `CONSUMER_ENABLED` are independent. Tests of mocked OCR are not actual OCR validation. Must report exact SHA, test cases, artifact types (PDF vs scanned photo), output error counts, approvals and provider spend. NO `CONSUMER_ENABLED` while release/owner restrictions remain.
