## Mandatory contract
1. **Routine templates are plans, not evidence:** named template, selected days, user local timezone/effective date, optional time, selected activity, target range and planned sets/load; owned, versioned, editable, pausible and deletable. Create a routine from a successful reviewed activity or Activity menu; do not convert past entries to planned future entries.
2. **Today/Activity 'Log today' quick action:** visible due activity with clear editable actual metric(s), sourced date, primary save; no mandatory multi-screen selection. A user with no routine retains ordinary activity add/repeat. Compact editorial UI for both 390 and 1440; same contract at 320/768/200% zoom and four themes.
3. **Steps require first-class actual measurement with scope:** `steps: nonnegative integer | null`; target min/max separate; distinguish session walking-pad manual steps from whole-day Watch/device steps and intervals. Never auto-fill actual from target/previous instance, minutes or distance. No naive sum for overlapping sources. Explicit activity completed with count unknown is allowed, but null stays null.
4. **Scheduled occurrence identity:** stable tenant/template/local-date/version occurrence key; local day and DST must not silently duplicate; `due/skipped/unrecorded/completed/rescheduled` separate; bounded future materialization. Historic completion attached only to an acknowledged saved canonical activity; template edits default future-only, distinct from edit one occurrence; holidays/missed are not zeros or failures.
5. **Canonical history:** actual recorded activity and independent strength sets saved into existing source/owned activity history, Today/Progress/Athlete/export/deletion from same record. Reuse existing idempotent save, corrections and account guard; new duplicate occurrence protection + retries/409 tests. Multiple genuinely distinct workouts permitted.
6. **Permission/source truth:** manual counts and devices distinctly named; native sync remains unsupported until an actual authorized bridge. Target-step versus actual and planned versus performed distinctions survive all renders and downstream BOI analytics.
7. **Accessibility and quality:** inline 1-number quick log accessible and fast; no nested administration calendar, punitive streaks or giant repeated panels. ≥44px targets, keyboard/VoiceOver where available, focus and return, Today safe area, dark/light Everyday/Athlete, empty and save/retry/offline statuses. Test with real browser evidence before PASS, don't require screenshot *deliverables* for owner routine decisions.

## Implementation sequencing — do not block unrelated v0.6
- **R1 walking quick-log:** step count typed and source scoped, one actual/day with explicit date, workday routine setup and due Today, confirmed save; preserve manual activity entry.
- **R2 general recurrence:** selected weekdays, effective dates/timezone, skip/reschedule/pause/edit one versus future, duplicate/retry and date/clock tests.
- **R3 rich reusable activity:** strength A/B multi-component sets, cycling, running, swimming, yoga, compound workouts, partial sets, independent original-unit actuals; no phantom completed sets.
- **R4 device and intelligent follow-up:** overlap/dedup rules on genuinely connected sources, optional low-burden notifications only with consent and actual backend support; BOI suggestion/plan/performance/outcome linked but not equated.
