# Bloom v0.6 — Multi-pathway extensibility and continuously updated evidence gate
Date: 2026-10-31 | Owner-approved architecture requirement | Status: requirement approved, **not implemented or release-accepted**.

## Product outcome
Bloom's Living Microbiome & Molecular Intelligence must grow across **multiple biological pathway families** primarily by importing and approving structured scientific knowledge, not by implementing one bespoke code path per organism or study. The B. fragilis/BFT/claudin-4 example is a rigorous **acceptance fixture, not the architecture's scope**. Preserve the existing modular monolith and canonical v0.6 literature discovery, evidence registry, typed knowledge graph and independent recommendation engine. Do not build a second crawler/database/graph/recommender or new paid provider.

## Mandatory acceptance — general-purpose knowledge graph
**V06-LIVE-EXT-01**: Entities and typed edges accommodate foods, nutrients/compounds, organisms/taxa/strains, microbial/host genes, enzymes, reactions, metabolites/toxins, human proteins/receptors, pathways and experimentally observed endpoints. Edge labels specify organism/assay resolution, experimental system, whether measured vs inferred, context, direction, source and evidence confidence. Schema extension is allowed only for genuinely new relationship *types*, not per-new-pathway code.
**V06-LIVE-EXT-02**: Exercise **at least five materially different pathway families** with pinned reviewed reference fixtures and end-to-end explorer navigation: (a) strain/toxin/host receptor (BFT), (b) fermentable fibre → microbiota → SCFAs, (c) polyphenols → microbial biotransformation and metabolites, (d) bile-acid transformations → host signalling, (e) tryptophan metabolism → indole compounds/host signalling. Additional exercise/nutrition pathways can follow. Tests must include direct and uncertain links, null/conflicting evidence, variable assay resolution, and sources with absent personal data. A pathway is not counted as validated until actual published sources and endpoints are reviewed by Biology.
**V06-LIVE-EXT-03**: A new reviewed study/claim/relationship should become available through **versioned data ingestion and evidence approval**, without a custom UI component, endpoint or client release for each pathway. A generic graph view answers what, why, potential influences, supporting studies, and what user's actual assay establishes. At least one previously unknown-to-fixture relationship must pass the ordinary ingestion→review→render workflow with no pathway-specific code changes.
**V06-LIVE-EXT-04**: Show coverage honestly: unsupported links are unresolved/unknown, never fabricated; distinguish absence of evidence from evidence of no effect. Claim-level citations, study context, quality limits, stale/retracted/contradictory states and update dates are visible. General Explorer functions with no user data, AI key or active provider.

## Automatic discovery, controlled knowledge publication
**V06-LIVE-UPD-01 — Automated, budgeted source monitoring:** existing source adapters periodically query approved PubMed/NCBI, Europe PMC and Crossref identifiers/revisions/retractions; ClinicalTrials.gov when relevant. Use saved, versioned queries and an expanding seed set from **approved** entity IDs, synonyms, study keywords and citation links (not unrestricted web crawling or raw private user genotype/taxon text). Rate limits, bounded per-run pages, inexpensive polling, retries/backoff, source terms and data provenance required. No personally identifying or health data sent to literature services.
**V06-LIVE-UPD-02 — Deterministic identity and dedup:** stage DOI/PMID/PMCID, version, dates, source span, publication/retraction state, taxonomy IDs, aliases, study design and endpoint. Match aliases conservatively; ambiguous species/strain identities remain review required. Identical/updated/retracted papers generate idempotent update events rather than duplicate active edges.
**V06-LIVE-UPD-03 — Candidate extraction, not autonomous medical science:** optional AI can propose **typed evidence assertions** anchored to source spans, accurately preserving model system, population, intervention amount/duration, comparator, outcomes including null/harm, confidence and contradictory studies. Schema and DOI/source checks reject unsupported content. Without AI, metadata discovery and curator-led structured entry continue to function.
**V06-LIVE-UPD-04 — Scientific review gate:** candidates are *not published*. Biology/reviewer approves exact source-linked wording and graph edges as education, requests changes, or rejects. Approved claims version immutably; publishing and withdrawing are authorized activities logged with reviewer/date and source snapshot. Automatic updates may mark an existing approved claim stale or withdrawn and hold dependent content; they cannot silently strengthen evidence or create a new personalized action.
**V06-LIVE-UPD-05 — Separate recommendation promotion:** educational evidence and ordinary wellness recommendation rules remain different approval levels. New papers, graph path traversal, machine-assigned confidence or taxon change cannot automatically increase or prescribe a personal food/fitness action. Any future action ID requires independent evidence, user-preference/allergy constraints, risk/claim review and CA/US intended-use determination where relevant. Preserve the owner's research-informed, non-diagnostic wellness scope.
**V06-LIVE-UPD-06 — Efficient operations and quality:** establish source-status/lag, number of discovered/candidate/approved/rejected/retracted claims, unresolved identity collisions and review queue size; minimal privacy-safe audit logging. Avoid unlimited review backlog by routing high-quality/changed evidence for human attention and aging out low-relevance candidates; do not claim comprehensive coverage of all science. Use no new paid infrastructure unless authorized.

## Technical and validation expectations
- Extend existing v0.6 contracts and source-backed graph rather than build new tables/components where existing ones suffice; use generic stable claim/edge IDs, versioned schema and backward-compatible migrations.
- Include negative test species → toxigenic strain → active toxin inference; relative species-abundance dietary change → toxin inhibition; mechanistic mouse/cell finding → human prevention; unverified study → approved UI; retracted paper → still-active actionable rule.
- Test two-account isolation for optional personal overlays; no report, no AI and source API outage fallback; review permission and change history; deterministic fixtures and same-article replay; live citation content only where licensed.
- Run bounded scheduled discovery when approved/implemented. **No automation or scheduler is claimed active by this specification**; its implementation is a later Codex slice after v0.5 core gates and applicable v0.6 prerequisites.
- Preserve the v0.5/v0.6 completion modularity audits and Codex token-efficiency policy. Do not spend ordinary v0.5 development tokens on research-platform refactoring.

## Completion evidence
Codex records exact commits, fixture references across five pathway families, source/review pipeline tests, real Explorer capture, permission/offline behavior and independently approved science/UX. Status stages: implemented / tested / deployed / independently accepted. No v0.6 acceptance if graph requires custom application changes for every added reviewed mechanism, if automated research changes food recommendations directly, or if publication/retraction feeds silently modify personal measured data.
