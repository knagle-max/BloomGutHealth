## 1. Governing rule: eliminate waiting, preserve truth

No `BLOCKED_USER_INPUT` merely because Architect can decide and already has a safe default. Convert such entries to **RESOLVED_DECISION**, **SOURCE_AVAILABLE**, **READY_ENGINEERING**, **IMPLEMENTED_PENDING_ACCEPTANCE**, **DEFERRED_APPROVED_SCOPE** or a named **EXTERNAL_ACTIVATION_GATE**. Not all are code work; statuses distinguish:
- `RESOLVED_DECISION`: architect/owner choice settled, no further question.
- `SOURCE_AVAILABLE`: controlling source located; no assertion code or complete review is done.
- `READY_ENGINEERING`: approved scope and source/fixture adequate for meaningful coding; code verification still required.
- `IMPLEMENTED_PENDING_ACCEPTANCE`: actual coded state/evidence documented; independent release tests still open.
- `DEFERRED_APPROVED_SCOPE`: explicitly staged behind v0.5 core and not a v0.5 completion blocker, with return milestone.
- `EXTERNAL_ACTIVATION_GATE`: credentials, licence, paid commitment, source-specific clinical claims, irreversible operation or physical real-device/human acceptance; **specific feature only**, never generic code freeze.
- `TECHNICAL_DEPENDENCY`: bounded code/environment/CI/deploy issue with developer-owned next action.
- `REPLACED_CRITERION_PENDING_TEST`: historical verbatim acceptance absent but Architect has written an honest successor; **cannot certify original wording**.

No row is “implemented,” “accepted,” “clinically cleared,” or “security approved” merely because its document or replacement specification now exists.
