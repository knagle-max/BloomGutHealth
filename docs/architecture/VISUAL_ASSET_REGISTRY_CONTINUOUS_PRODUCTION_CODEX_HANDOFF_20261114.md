**Existing app delivery mechanisms remain canonical for image lookup**: `client/src/content/editorial-media.ts`, `client/src/components/EditorialMedia.tsx`, `shared/scientific-visuals.ts` and `shared/data/scientific-visual-assets.json`. Do not rename or invalidate existing identities merely for consistency.

**Roles:** Brand & Visual Design Specialist = art direction, optical/material quality, composition, responsive crop and aesthetic acceptance; Biology = additional anatomy/mechanism accuracy for educational factual visuals; Architect = source-to-requirement reconciliation and priority; Codex = production pipeline integration, registry/API/asset references, tests and rendered verification; Security/Legal = privacy, external generator data use and rights/retention, evaluated only where relevant. Owner does not need to procure photos; AI is preferred first-party creation mechanism.

## 3. Registry schema, validation and lifecycle (Codex implement)
- Use exact stable IDs `BVA-0001`…`BVA-0028`; next `BVA-0029`; never recycle IDs after retirement. Add a schema under existing shared/tooling conventions and validate registry in CI.
- Required fields per row: `id, name, route/component, purpose, category, subject/brief, composition, scientificAccuracy, mode/theme applicability, textPlacement/negative space, aspectRatio, targetDimensions, responsiveVariants, transparent, outputFormats, promptBrief, priority, impact, sourceRelation, lifecycle, productionStatus, filePaths, integration, review, statusEvidence`. Enrich nullable fields for actual generation model, prompt version, source SHA, image SHA, asset rights, alt text, crop focal point, approval receipts and release scope. Validate no duplicate IDs/physical path collisions, invalid format/aspect, phantom review, retired ID reuse, or unknown production state.
- Allowed lifecycle in order: `Identified → Briefed → Approved for Production → Generated → Design Reviewed → Scientific Reviewed (when educational) → Approved → Integrated → Visually Verified`, plus `Retired`. Record **N/A by accountable reviewer** for scientific review of truly decorative art rather than fictitious PASS.
- Require evidence with each state: `Generated` requires first-party file paths, content digest, prompt/model record, dimensions and rights-status; `Approved` needs design approval and scientific approval where applicable plus rights clearance; `Integrated` needs valid actual component/slot binding, verified resource handling, responsive crop and nonempty alt/intentional decorative alt; `Visually Verified` requires actual rendered screenshot(s) at SHA/viewports/themes and regression test result. Code/reference alone must never set integrated or visually verified.
- An inherited already-live asset may be tagged `legacy-reference` or `reuse-review` in mapping metadata, and should only receive mature lifecycle state after actual image/placement/source review—not presumptively via metadata presence. No default 'Approved' in seed.

## 5. Continuous normal-development policy
**Mandatory lightweight question on every relevant change:** “Does this page/component/educational content benefit materially from a custom asset?” If yes:
1. Search registry and existing editorial/science catalogues for suitable approved asset.
2. Reuse appropriate asset; if existing art is inadequate, record replacement relationship and keep current image until safe.
3. If new, assign next BVA ID, complete source/crop/responsive/prompt brief and `Identified` or `Briefed` status.
4. Add `data-bloom-asset-id` (or typed equivalent) to reserved UI slot with attractive zero-dependency fallback; link requirement via the central adapter.
5. Add/backlog the requirement by ID, assign priority, scene-specific visual/science reviewer, and never claim production has happened.
6. Generate a coherent batch via an **actually available approved** AI image capability; if no such capability in Codex's environment, report the blocker but maintain elegant placeholder, avoid asking owner to source photos.
7. Review science when factual anatomy/molecules are depicted, design for all compositions, rights/privacy/copyright, real file geometry and screens, then integrate and evidence-test. Repeat after replacements and changes.

**Do not insert new artwork where it adds nothing.** A simple vital information form may only need the shared theme and strong typography. "Asset considered: no artwork justified" is a legitimate audit finding, not an error.
