# BLOOM-LOCAL-AI-01 — Shared On-Device Intelligence
**Product Owner requirement:** v0.6 **P0 architectural foundation / measured promotion gate**, with scoped implementation and device validation. **Status: APPROVED for engineering, NOT a claim of supported model/browser, performance, physical iPhone acceptance or deployment.**
**Date:** 2026-11-06. **Implementation owner:** Codex Developer. **Final gate:** integrated specialist testing, not ongoing interim permission.

## Exact owner requirement
“Bloom shall evaluate and, where validated, implement reusable on-device machine-learning inference for natural-language food, exercise and lifestyle interpretation. The implementation must operate without mandatory third-party AI services, produce schema-validated outputs, preserve user review and source uncertainty, and benchmark against existing deterministic parsers using realistic held-out inputs. Device capability, memory, download size, latency, battery impact, privacy and failure fallback must be tested on supported browsers, including physical iPhones. A model shall be promoted only where it materially improves interpretation quality without compromising data integrity, responsiveness or user control.”

## Architecture decision: shared model interface, not another fixed parser
1. **One reusable browser-side inference contract** for `food`, `exercise`, and `lifestyle` description tasks (domain-specific schema adapters, not forced identical nutrient/exercise fields). Preserve open vocabulary, novel ingredients/movements, varied phrasing, mixed items, quantities/units/preparation, intent/negation/time and unknowns. The core experience never requires a provider account or network call to a third-party LLM.
2. **Routes of interpretation:** (a) validated on-device ML when compatible and genuinely better; (b) existing deterministic parser + review when ML unavailable/declined/outperformed; (c) user-editable manual entry always. The existing consented server AI route may remain an **optional**, clearly disclosed alternative where authorized, never a required dependency. No new paid service or data transfer solely for this requirement.
3. **Browser/model candidates evaluated, not presumed:** Codex should benchmark feasible lightweight browser runtimes (e.g. WebAssembly/CPU and optionally WebGPU/WebNN as actually available), models, tokenizer and asset packaging against support targets. Don't assume iOS Safari supports a particular acceleration API or model memory footprint. Prefer progressive lazy loading, safe cache strategy and versioned integrity-checked model artifacts, with a cancel/unload path. No surprise multi-hundred-MB download or service-worker forced inference.
4. **Schema and provenance:** model outputs are *draft interpretations*, strict typed validations with exact verbatim source spans/attribution for identities, counts/units and preparation/intent; deterministic bounds/negative checks prevent hallucinated quantities, wrong association or missing-as-zero. If source span unsupported, mark `needs_review` rather than accept. Never autonomously save, infer completed workout, measured nutrients, health effects or clinical/diagnostic recommendations. Existing canonical `Food`, `Activity`, experience records, meal review and source/provenance are authoritative.
5. **Privacy and control:** local inference should keep description and intermediate features in device memory whenever possible; do not upload text by default, log raw prompts, enroll in model training or persist sensitive inference cache. Model assets are shipped/licensed under validated distribution terms; document that model download still uses Bloom hosting/CDN and isn't necessarily available on first offline use. Explain local versus optional server processing accurately. Respect account switching, source deletion, logout and browser clear, purpose and consent policy.
6. **Resource management:** bounded concurrency, timeouts and responsive UI, no main-thread lock, abort on navigation or edit, protection against denial-of-service input, OOM/slow device fallback; no fake “offline ready” state until model downloaded and proven functional without network. Fail safely without losing source text or reviewed manual edits.

## Promotion evidence, tests and support matrix
- Build a **held-out, independently authored** realistic input corpus covering dietary descriptions, mixed restaurant meals, unknown foods/brands/amounts, exercise owner example (45-minute run + 10 pushups + bench 3x10x225 lb + 20 bodyweight squats), novel movements, supersets, colloquialisms, lifestyle events, ambiguity, multilingual only if supported, contradictory/negated facts, malformed, adversarial and long text. Split into train/dev/test; never optimize on hidden test cases. Log model version, tokenizer, runtime, schema and corpus provenance without user data exposure.
- Compare current deterministic baseline, local candidates and any separately authorized server-AI benchmark by **field-level precision and recall/coverage**, exact item and numeric/unit association, unsupported-inference/hallucination rate, confidence calibration/abstention, edit burden, user task completion and actual persist/reload correctness. “Material improvement” must have an a priori measurable decision threshold selected and recorded from representative tasks **before looking at held-out results**, and cannot be achieved by simply returning more guessed fields.
- Record for supported iOS Safari **physical iPhones**, Android Chrome and other browsers where claimed: compatibility/API path, first download bytes and time, cached/offline start, median/p95 inference latency, peak working memory and OOM, model initialisation, CPU/thermal/battery impact over sustained sessions, background/tab switching, network absent, private mode/storage eviction and low-memory older hardware. Run on real devices, not simulator alone; keep support claims scoped to devices actually tested. Define explicit performance budgets ahead of promotion based on acceptable actual workflow responsiveness, battery and download affordance; no invented pass thresholds.
- Robust fallback tests: WebGPU absent, WASM only, storage blocked, memory pressure, network/model load blocked, model initialization fails, cancellation while reviewing, model timeout, unrecognized input, stale cached model, expired/licence invalid source, revoked purpose, and UI review corrections. Re-run actual capture→draft→review→save→reload with source/field links, user edits and no external transmission unless optional separately consented.
- **Promotion states:** `EXPERIMENTAL_LOCAL_EVALUATION` → `ENGINEERING_TESTED_ON_SUPPORTED_DEVICES` → `DEFAULT_ELIGIBLE_FOR_COMPATIBLE_DEVICES` only after measured quality improvement, source fidelity, safe UX and performance; device-specific rollback/kill switch and deterministic fallback. Before that, local inference can run internally or behind the existing privileged **Show development features** capability, without representing a live public capability.
- Present R&D work to final Branding/UX, User Testing, Security, AI/ML and Science where applicable as one integrated evidence packet. Do not block coding on interim approvals or pretend model output is a clinical measurement.
