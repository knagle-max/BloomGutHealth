# BLOOM-NUT-RECIPE-20261127-R1 — canonical recipe-to-food-journal product and implementation directive

**Owner product direction:** November 27, 2026. **Disposition:** approved core product direction with architectural/scientific safeguards. **Owner's explicit clarification (same date) governs prioritization:** Bloom must provide a **comprehensive practical recipe library** in which a user **follows a real recipe** and then **logs the entire consumed recipe portion in one action**, automatically entering **every included ingredient and all source-supported nutrients** into the existing canonical food journal. Never require the user to rebuild a known recipe by individually logging each ingredient. This is the **primary consumer outcome**, not a distant optional feature that waits for full microbiome/genetics/AI modelling.

## 1. Required end-to-end user journey (binding)

1. **Discover and cook:** Browse/search/filter genuinely distinct, practical Bloom-curated, lawful-source or user-owned recipes. Each recipe shows familiar title, actual ingredient list with quantities/units, servings, equipment/time, cooking steps, accessible prep instructions and concise nutrition summary.
2. **Ingredient-linked data:** Ingredients resolve against the **existing** canonical food/source registry, with correct preparation, quantities, edible weights, nutrient identities, source version and per-nutrient known/unknown coverage. A recipe is not just a photo, unstructured text or generic calorie estimate.
3. **Adjust actual batch:** User can review/change the actual quantity, substitution, omission, cooked yield or serving count. The authoritative deterministic calculator recalculates nutrient contributions. Missing oil/salt/portion/source stays unknown or explicitly partial; do not fabricate.
4. **Log what was actually eaten:** A clear **Log meal** (or equivalent) action opens a compact confirmation of the **portion actually consumed** (e.g. 0.5, 1, 1.5 servings or measured grams), meal timestamp/type and any confirmed substitutions. On explicit confirmation, **one atomic/idempotent save** creates the existing canonical meal/consumption record with **all included original ingredient identities, quantities, source-grounded per-nutrient contributions and total/per-nutrient coverage**, linked to the recipe revision. **Do not make the user log every ingredient manually.**
5. **Everything updates:** After save, existing Food journal, Today's confirmed intake, recorded nutrient totals/coverage, Progress and eligible biological context use the **same canonical record**, not a parallel recipe ledger or independently computed totals. Planned/favourited/prepared recipes remain **not consumed**.
6. **Repeat easily:** Recent/favourite or personally edited recipe can be used again and logged quickly with last confirmed portion; still require explicit consumption confirmation. Editing the template later must **not** mutate past meals; correction/deletion use existing canonical revision and source semantics.
7. **Offline/AI-disabled core:** Recipe catalogue, ingredients, deterministic nutrition calculations, preparation instructions and one-action logging must work **without a paid recipe API or external AI**. AI proposals are optional and cannot invent composition or save food.

**Example acceptance flow:** a four-serving chicken gnocchi soup with known chicken, gnocchi, vegetables and broth. After cooking, the user confirms **1.5 servings** (or measured prepared grams if actual batch yield and allocation are supportable). Bloom creates **one canonical consumption event** containing the **0.375 batch fraction** of every included source-resolved ingredient and each compatible, available nutrient—not four separate manual logging interactions. If some seasonings/oil are unmeasured, show known nutrient subtotals as **partial**, not false complete zeros. Source dates/units/calculation version and the exact original recipe revision remain attached. The sum must match logging equivalent individual ingredients with the same identities, weights, source definitions and calculation version within explicit rounding tolerance.
