# Bloom — Architect decision: AI-assisted open-vocabulary Activity Describe
**Date:** 2026-11-06 | **Priority:** P0 existing broken Describe experience; full AI service integration is P0/P1 scoped by authorized provider/cost/consent; implement and test without repeating owner approval.
**Owner direction:** Do NOT constrain natural language workout logging to a known exercise list, rigid separators or required syntax. Permit AI specifically for converting an arbitrary user's exercise description into accurate editable structured workout observations. The deterministic parser remains privacy/offline/provider-unavailable fallback, NOT the limiting primary model.

## Current verified baseline and supersession
- In `client/src/pages/ActivityLog.tsx`, `describe()` calls synchronous `describeActivityParts(description)`; the UI promises `Local text matching; no AI or external provider`.
- `shared/activity-capture.ts` has seven generic activity choices and a regex segment parser. It missed the owner example `Ran for 45 min then did 10 pushups, bench press for 3 sets of 10 reps for 225lbs, 20 bodyweight squats,` and displayed only Running and generic Strength exercise.
- `docs/architecture/ACTIVITY_DESCRIBE_MIXED_EXERCISE_PARSE_REGRESSION_2026-11-06.md` remains binding for exact source and E2E output. **This newer architectural decision expands its earlier `no new AI service` limitation:** no *unnecessary duplicate* service or model; reuse existing authorized server-side AI integration if present or build the smallest compatible adapter with separately controlled provider activation. The owner has explicitly requested AI specifically for this workflow, including unusual/out-of-catalogue movements.

## Experience and required results
**Natural freeform entry is first-class:** text, colloquial/spelling variants, movements not in any exercise table, brand-specific exercise names, machines, yoga/swimming/hiking, circuits, supersets, paired movements, multiple weight units, repeated exercise blocks, duration, distance, pace/speed, incline, RPE/RIR, unilateral counts, rest intervals, warmup vs working sets, planned vs completed intent, and new activities. No fixed-vocabulary classifier may overwrite a user's exact movement. No language-format instruction to users beyond `Describe your workout in your own words`.

One-step `Review workout` yields a **draft** list containing original verbatim exercise labels and canonical type only when defensibly recognized; all source-reported fields mapped to existing canonical fields where supported, with additional observations stored in appropriate existing notes/extensions if the schema lacks a field, never misrepresenting an omitted field as zero. Source ranges/phrases mapped to each proposed activity and property, uncertainty labeled per field. Reviewer can edit/remove/add any row; edits never reinterpreted or replaced silently. User confirms before actual persistence. Render clear source, set/repetition/load/time and `Needs clarification` only for materially ambiguous attributes.

**Exact owner's example expected:** Running 45 minutes; push-ups 10 reported bodyweight reps; bench press 3 sets × 10 reps × 225 lb each; bodyweight squats 20 reps. No invented duration for strength, automatic calories, guessed weights, inferred completion, heart rate or max effort.

## Architecture — AI interpretation, deterministic authority
1. `User description` → authenticated server-side, **purpose-specific authorized AI inference if available** → strict versioned structured schema (exercise span/name, recognized activity class as optional, sets/reps/load/value/unit, bodyweight flag, minutes/distance/pace, reported vs inferred, explicit ambiguity, confidence-style evidence by span and review needed). No AI authority to persist, change prior records, invent exercise IDs, run code/tools, perform clinical risk assessments or generate unsourced quantities.
2. Parse model output through strict schema and **deterministic post-validation**: preserve all original segments (coverage), check counts/unit bounds, explicit words-to-quantities and physical plausibility without assuming sports performance benchmarks, duplicate/repeated movements, ensure no invented exact numbers or dropped activities. Strong source-to-output grounding (prefer explicit matched verbatim source substrings for each numeric field); any unsupported value becomes null/needs-review. Enforce response and input limits and reject prompt-injected instructions within the description.
3. Canonicalize **type** through existing `activityChoices` only where possible. Preserve arbitrary `title`/movement label, not generic `Strength exercise`. Keep proper account ownership, original captured text, revision history, idempotent save and completion state semantics. AI proposal remains local draft until user confirms; never treat AI explanation as user's performed action.
4. If no provider/consent, outage, timeout or model low-quality response: deterministic fallback improving current parser; preserve segments/open-vocabulary names and known amounts, **label `Basic matching`** and prompt per-row corrections. Never silently fail or block manual/select/repeat activity logging.
5. **Provider/consent/cost:** The text is sensitive personal activity data. Do not transmit to an external AI endpoint without explicit appropriate existing purpose-specific user disclosure/consent, real approved provider/rights/region/data retention terms, server-only secrets and account opt-out. A generic `Show development features` toggle is not consent. The owner requested feature scope, **not new unbudgeted paid billing**; reuse authorized existing endpoint/service and free/in-house model if feasible, or code/test stubbed adapter and mark external activation specifically gated. If AI available and user opts in, it should be a seamless primary path; otherwise full local capture still works. No AI model training on original health text without separate consent. Favor minimum-text dispatch, encrypted transit, no raw prompts in ordinary telemetry, rate/budget caps, retries/fallback. Public-safe AI activity extraction is distinct from medically sensitive shadow outputs.
6. **Do not require a fixed exhaustive exercise taxonomy.** Optional known movement matcher for downstream analytics and autocomplete is a secondary enrichment, separate from the actual captured activity name. Unknown or novel movements remain fully loggable and editable.

## Test contract
- **Golden exact example** from owner (with/without trailing comma) yields 4 correct activity rows including 3 bench set records and 225-lb unit with unconfirmed completion; no generic collapse. Test with AI model result under actual schema validator and fallback model-unavailable path (fallback may flag ambiguity but must not drop all source-named movements).
- Variation matrix: `did 3 rounds of 12 kettlebell swings, 8 goblet squats, then 500m on the rower`, `bike 25 min, single-arm DB rows 3x12 @ 40lb each side`, `2km run then supersets pull-ups and curls`, unknown invented exercise label, yoga class, weights as ranges `135/155/175`, negative/planned clauses `planned 5 sets but only did 3`, repeated movements, supersets and time/rep ambiguities, multilingual text if claimed, commands embedded in input. Preserve ambiguity and source phrases; never fabricate load/duration/completion.
- Validate held-out human-authored descriptions (not only curated prompt examples) for field precision/recall and hallucination count, source coverage, unknown-field preservation, edit rate and UI review success. Compare deterministic baseline and AI; do not infer that a single LLM run is 100% accurate. Model/version/fixture and current code SHA tracked, structured output negative tests, outages, cancellation, leakage, provider scope, account isolation.
- Real screen UI: 320/390px, keyboard, accessible unknowns/expandable rows, accurate save→reload, correction/undo/idempotence. Actual hosted model activation is verified separately from mocks; no misstatement about AI being live if it isn't.
- Privacy: user-visible disclosure `AI-assisted interpretation` when active, with source data retained only under current account authorization, no external provider call absent permitted consent, no medical advice/predicted physiology.
