## Binding UX and data decisions
1. **Primary workflow:** In Saved laboratory sources, display for each source *human readable* original/confirmed laboratory identity (or “Laboratory not recorded”), reported date(s) with date precision, number of active results, report/specimen ID when explicitly supplied, correction/source state, `View results & charts`, `Manage laboratory & reference ranges`, and separate destructive `Delete report`. Existing old reports remain accessible and editable; never require reimport. Independent results without a report group must not silently form a report from a date alone; allow explicit safe migration/link review if scientifically/syntactically justified.
2. **One canonical report metadata owner:** Source-immutable imported original labels stay attached to each original result. A user-confirmed **report provider identity** is a separate versioned metadata annotation keyed by authenticated owned stable original report-group identity, preferably importId+explicit report/specimen identifiers as validated by current grouping. The annotation includes provider enum (`LifeLabs`, `Dynacare`, `other`, `unknown`), named raw provider if other, confirmed testing province/territory incl `SK`, optional explicitly sourced location, source of assertion (user-confirmed vs original), timestamp, expected revision, audit/correction history, and linkage to source group. **Do not overwrite `Lab.laboratory` or reinsert 27/17/26 records** just to update report metadata. A minimal additive per-owner report-annotation storage table/entity is acceptable only after validating current storage cannot safely express authoritative report-level revisions. Do not create a second lab observation or provider scientific range registry.
3. **Overlay preferences:** One authoritative report-scoped choice `original-report | verified-provider-comparison | none`, with chosen provider/province if comparison, compatible with existing `LabOverlayChoice` and report group keys. Prefer same owned report annotation if robust; if session-only pending safe persistence, explicitly disclose that and ensure **all entry points share the same live state**. Choosing LifeLabs as *performed laboratory* never silently switches on LifeLabs comparison or replaces its original limits. Changing lab/province must invalidate stale incompatible display verification, cached range context, stale conclusions, and claim status, but never alter actual observation data.
4. **Scope/collection specifics:** Provider, test province, original label and location shared at report level; method/assay, specimen, fasting, collection-age and sex reference category remain fact-specific, may need result-specific reviewed input. Prompt only if a verified comparison exists and the missing value would enable a scientifically valid match. Current profile demographics cannot silently substitute historical collection context; no invented method or specimen. Date corrections continue to reflect source truth.
5. **Source/permission lifecycle:** Ownership enforced at server request AND commit; versioned atomic changes and 409 on stale identity/revision; idempotent receipt and safe retry; source deletion removes linked annotation and preference; original report revisions/corrections remain. Read scopes, account-switch/cache/logout, export report annotations with explicit provenance, erasure, encryption/retention protections via existing policies. Resolve original label disagreement and separately dated results transparently; no inferred third-party disclosure.
6. **Navigation / visual:** `Manage laboratory & reference ranges` opens a focused accessible report-level panel from Saved laboratory sources (not an unrelated chart), readable report title/date/count, immutable source label vs user confirmation visibly distinct, lab/provider/province/optional location and comparison preference. Present coverage/unavailable reasons before enabling selection; preserve original interval priority. Provide direct `View report results and charts` deep-link; legacy chart control becomes shortcut to **same** canonical state or delegates to the panel, not competing settings. R4/M1 premium editorial UX, no medical admin form walls; 320/390/768/1440, Everyday/Athlete, light/dark, keyboard/VoiceOver and 200% zoom.
