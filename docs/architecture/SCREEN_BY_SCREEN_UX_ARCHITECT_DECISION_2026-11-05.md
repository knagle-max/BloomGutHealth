## Binding decision and boundaries
**APPROVE REVISE CURRENT COMPOSITION; KEEP FUNCTIONALITY, BRAND, NAVIGATION AND DATA SAFETY.** The source is a precise UX layout/wording specification, *not* a requirement to invent new data contracts, parallel UI framework, dashboards, duplicate routes, replace existing tested flows or hold engineering while every visual detail is redesigned. Reuse existing React components and canonical `client/public/brand/design-tokens.json` and `design/bloom/flagship/2026-10-26/contracts/UX_BLUEPRINT.md`. Everyday green/light and Athlete navy/blue remain. No global compulsory `CompanionHero`; only use a hero if it is the page's actual primary action. No arbitrary 2–4-card limit on analytical deep-dive views.

The product criterion is **single immediately legible job on a default route, with full science and original data one deliberate interaction away**. Exception/caveat still visible next to the affected control when material for safety or decisions. Keep original units, source report/dates/method, chronology, consent, privacy/export, full genetics/organism catalogues, nutrient coverage and undo/edit behavior. The `one dominant CTA` rule applies to task entry screens, not all tabs/analytical contexts. User-experience copy should translate internal statuses, never hide essential warnings.

## Specific reconciliations
1. **Genetics latest owner/Architect instruction wins.** Source-backed observed educational results may appear without a blanket specialist clinical-claim approval. Separate individually consequential personal biological/clinical claims still need relevant evidence, consent, assay and clinical/legal scope. The new 2–4 visual count and older 0–5 relevance hypothesis are both *non-binding* defaults: never pad or hide valid observations solely to meet a number.
2. **No new broad release blocker.** This is an eight-route composition audit with implementation **when a route is actively touched**; prioritize genuinely confusing/broken P0 Today, Food, active Athlete and Biology landing. Do not spend several sessions on visual-only rearrangements ahead of native Viome PDF import, core user journeys or genetics source correctness.
3. **Source availability:** The source commit is explicitly known even though the two files are absent from the development branch. Developer can read at the commit, or selectively transfer the two small design text/JSON files if needed, without re-requesting owner upload or touching unrelated source files.
4. **Clinical and permissions:** Plain-language translation of `source revision`/`provenance`/`assay normalization unresolved`/`partial nutrient coverage` must not remove the relevant underlying raw metadata or conceal a genuine high-risk caveat. Keep sanitized report view, never original unredacted Viome PDF.
5. **Release checks:** 390px default/empty/error first viewport purpose + one primary action where applicable; 320px and 200% zoom; keyboard and touch; no draft loss; real save ack; exact-SHA screenshots before/after **only for materially changed screens**, with Branding review of real build and UT uncoached comprehension. No made-up live acceptance. One canonical `bloom.screen_simplification.2026-11-05` contract; avoid a new test framework or blanket screenshots for untouched routes.
