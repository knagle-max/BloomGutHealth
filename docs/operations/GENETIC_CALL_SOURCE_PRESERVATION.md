# Genetic call source preservation — reader-first compatibility

The existing normalized two-letter genotype remains the canonical unphased call. Optional `sourceCall` stores only a bounded original token and the exact normalization version `uppercase-separators-unphased-order-v1`. It cannot contain a raw file, source row, filename, identifier, arbitrary prose, unknown metadata key or another transformation. Both raw/manual readers validate that normalizing the original produces the saved genotype. Reference placement, allele, consent, owner and evidence checks still apply separately.

The first release d8df5ce expanded readers without changing raw/manual producers and was verified live on the existing preview before enabling capture. Existing records omit the new field; no original spelling/order is reconstructed from old sorted calls. The explanation shows original versus normalized call when retained, otherwise explicitly states the original is unavailable. Case/separator/order normalization is not strand flipping, coordinate conversion or phase determination. Pipe-separated entry does not establish phase. Historical pre-normalization text cannot be recovered.

Untouched manual form rows retain supplied optional metadata; an edited token withdraws stale metadata and consent. This prevents an unaware source-label edit from erasing the original call. The subsequent producer slice captures new manual edits/pastes and selected raw SNP tokens; it never backfills untouched older rows. Raw files must have the supported four-column structure, with two-letter or -- calls at retained loci; indels/complex calls are not inferred. Unrelated whole-genome rows are still omitted. Older strict readers reject the new field, so the reader was deployed first. The field is within the existing encrypted owned payload; no database schema or external transfer changes.

Validation includes matching/mismatching originals, known-version enforcement, whitespace/no-call forms, rejection of oversized/private/free-text tokens, old-record compatibility, invariant interpretation/action boundaries, raw placement checks and authenticated HTTP owner isolation. Actual App checks expose a synthetic t|t original separately from stored TT while an older source correctly has no original text. No scientific or sensitive interpretation is newly enabled. New original-call metadata must remain readable if producer capture is rolled back; do not roll readers back while newer metadata exists.
