# Manual exercise set observations

`TrainingSession.actualSets` is an optional version1 observation object in the existing encrypted owned session. Up to100 rows carry exercise name, nullable actual reps and canonical loadKg, plus explicit completion. Legacy absence stays absent; null is unknown and zero is a recorded zero. No plan, wearable, readiness, growth estimate or set-completion inference is fabricated.

Readerfc6c4fc was deployed before ordinary controls. Unaware session updates preserve newer set observations under the existing owner lock. An explicit empty row list clears them. Existing create receipts cover the complete set payload; export and erasure use the same owned encrypted record. No new table, API, consent scope or calculation of workload, nutrition or session status.

The same optional editor is used for creating and correcting sessions. Load follows the existing mass-unit preference and is stored in kilograms. Fields freeze during create/unknown-response retry; verified create success resets them. Session corrections freeze fields while pending. The recorded summary distinguishes missing values and unchecked completion. Each current set has a read-only Previous reference: the most recent completed set in a completed owned session strictly before the draft start and now, matched by exercise text (case/spacing normalized) and ordinal among all same-name rows. Incomplete rows do not shift ordinal positions. No alias or program equivalence is inferred. Original recorded load units and dates are shown; missing values and zero stay distinct. No match says No prior set; pending/stale/paused/failed history withdraws references. Editing excludes the record itself. References never prefill or mutate current performance. Draft date edits update the cutoff. Marking a session completed remains a separate explicit existing action.
