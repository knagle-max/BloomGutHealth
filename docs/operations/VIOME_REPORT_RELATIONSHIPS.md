## User journey and source truth

After local PDF review (or optional typed findings), the app checks the current user's saved reports. A companion may be proposed only for the opposite document kind, a known identical collection date and compatible stated method/specimen. Date equality never creates a link. The user chooses the specific existing source and explicitly confirms the shared specimen; same-day entries show saved time and a short internal Bloom reference to remain distinguishable. Missing collection date stays standalone. Unknown method/specimen is not copied from another document.

The first standalone report is the internally keyed root; the companion stores optional `specimenEvent:{rootReportId,confirmed:true}` in the strict findings. The reference is an internal generated Bloom record ID, never a provider test/sample/kit ID. Both documents retain independent values, categories, source dates and positions. Either upload order works. Only one companion of the opposite kind can occupy a root; conflicting or deleted/foreign/untyped roots fail before insertion. Exported prior link metadata is stripped from a fresh import unless this review explicitly confirms a relationship.

Matching biological facts offer an explicit choice: keep an existing owned report, or acknowledge this is a separate biological source. The server rechecks exact effective names/categories/multiplicity, dates and method in the owner transaction before reuse. Ordering and printed layout positions do not create a new biological observation. Reuse is read-only and returns the selected existing ID, retaining its original source/provenance and relation; retries cannot create children or reactivate a deleted root. No semantic fingerprint is persisted and no raw bytes are hashed. Existing immutable write receipts keep their original behavior; their keys cannot be repurposed as a reuse command.

Saved native findings show source relationships and open the confirmed companion without mixing results. User-requested deletion is scoped to a native findings source and explicit confirmation. One transaction removes that report/derived children and unlinks surviving companions while preserving their biological content; quantified and other manual sources are outside this delete operation. Root deletion does not regenerate a source on historical receipt retry. Owned report cache variants are discarded after confirmed deletion, including if changing selection unmounted the deleting component. Another account's queries are excluded.
