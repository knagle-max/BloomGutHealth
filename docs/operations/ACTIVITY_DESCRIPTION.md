# Describe Activity: product contract and fallback

The user's promise is an editable interpretation of their own workout, preserving every distinct movement, source wording, quantities/units, unknowns and user corrections through save/reload. Arbitrary movements must not become a generic Strength exercise. No description alone confirms performed sets, calories, effort or medical effects.

The immediate regression contract is executable in `tests/activity-mixed-description.test.ts`: the exact owner sentence produces Running45min, Push-ups10bodyweight reps, Bench press3×10×225lb, Bodyweight squats20reps. Each parent has a stable identity and original source span; every set has a stable identity and pending completion. A simple count is one **reported bout**, not an asserted number of sets. Bodyweight is explicit metadata with unknown external load, never a measured0kg. Existing ordered loads, units/defaults, child edits, save receipts and historical records remain supported.

This delivered tier is **Basic matching**, not an AI model or the complete open-ended interpretation promise. It scans structural boundaries outside parentheses/quotes, preserves unknown source-named clauses, supports both name-first and count-first set syntax, repetitions and explicit weights. Quantity-list commas are preserved, including malformed lists that need review. Source spans describe original wording; edited values remain user-reviewed facts. Unsupported detail remains in the original source, rather than becoming a guessed metric.

Bounds:2,000characters,20activities and100set rows per saved entry, consistent with the existing canonical JSON model. Oversized initial text stays intact in the composer and is rejected before a partial review; no paste truncation or silent first20 acceptance. Unknown measurements stay null; repetitions are not minutes, rounds or distances. Planned/skipped sets remain explicitly planned/cancelled with completion false; planned cardio does not become measured performed minutes. Review/change remains available before saving.

Validation includes varied **development regression fixtures**, the independent owner-supplied example, actual App→HTTP→encrypted isolated SQL, row/set correction, original vs reviewed description, lost response exact retry, reload/mode/account isolation and320/390/dark/keyboard. These developer cases are not an independently held-out ML benchmark or physical VoiceOver acceptance.

The broader requirement remains open under `BLOOM-LOCAL-AI-01`: a shared source-grounded, schema-validated Food/Exercise/Lifestyle on-device interpreter, realistic independent held-out comparison, browser-worker/runtime evaluation and actual physical-device resource/privacy validation before default promotion. Optional separately consented existing external AI is not mandatory or implicitly authorized. No model has been downloaded, activated, benchmarked or represented as deployed by this fallback fix. Final specialist review is separate from continued safe engineering.
