# Optional microbiome food influence

One account-level setting, **Use my microbiome food recommendations**, defaults Off after migration and import. It lives in the existing encrypted precision context, independently of clinical context and general food preferences. Unaware context saves preserve it; ordinary context updates cannot forge it. Report/control metadata is stripped from clinical report context and AI planning inputs. No new schema, provider call, raw PDF storage or external sharing.

Settings appear in Gut report food suggestions, shared Food preferences and Profile Food preferences. The user selects one saved, reviewed eligible native food report and explicitly saves the setting. Other sources are not merged or automatically selected. Counts and category distributions come from the selected source. Missing collection/report dates remain unknown. A changed/deleted source supplies zero influence until deliberately selected again. Off never hides the report or restricts logging.

The first active ranking surface is the existing Meal planner Recipe library, including its existing priority endpoint. Allergies, exclusions, cooking availability and supported goals are applied first. The versioned resolver only orders within contiguous equal goal/taste-priority tiers. It does not change ingredients, nutrient values, targets or source categories. Report Enjoy/Superfood and Minimize/Avoid supply a bounded secondary ordering signal, not medical exclusions.

Source matching requires one exact existing prepared-food catalogue name or description, ignoring case/whitespace only. Ambiguous, conflicting, unknown, unlisted and ignored foods contribute zero. Two existing curated recipe labels, Cooked brown rice and Cooked quinoa, map explicitly to their existing cooked-grain catalogue IDs; these aliases do not broaden source-name matching. Milk/kefir/yogurt/oils and preparation differences are not conflated. Other mappings can be expanded only with verified exact identity.

Each returned trace compares actual On ordering against the unchanged Off baseline. **Microbiome report match** appears only with actual ordered-position contribution. Mere source presence uses **Listed in your microbiome report**. Why this suggestion discloses provider, original effective ingredient label/category, source date/page and priority limits. No overall recipe grade. Ignore persists canonical food IDs across source changes; restore and Turn off update the same account setting.

`GET /api/precision/microbiome-food` returns current setting/revision and owned eligible source data. `PUT` requires current `X-Bloom-Food-Actor`, strict confirmed control and current revision. Account-lock writes reject stale changes, foreign/unavailable sources and obsolete re-enablement after withdrawal; exact lost-response retries converge. Shared workspace write budget, owner-scoped query keys and account epoch guards apply. Report/source controls reset dependent planner and consent queries.
