# Shared local description contract — first prototype

Approved BLOOM-LOCAL-AI-01 engineering foundation, **not active model inference or default promotion**. `shared/description-intelligence.ts` defines separate food/exercise/lifestyle drafts under one versioned interface, preserving open identity text, explicit quantities/units, uncertainty and source spans. Spans use JavaScript UTF-16 indices and exact verbatim quotes. Quantities must match a complete literal number/word/fraction token; units need their own actual source token. Partial numeric/word/unit tokens, wrong-domain units, unsupported identity/preparation, cross-item spans, overlapping items, reused quantity spans and inconsistent per-set counts/order require review. Exercise has individual per-set loads and literal completion-not-confirmed; no nutritional values, diagnosis, clinical action, efficacy or model confidence fields. Canonical Food/Activity/experience records remain authoritative.

Source validation is necessary, **not proof of semantic association or correct interpretation**. A source phrase can still be ambiguous. Conservative English negation/future guards can require review; unknown identities are not limited to a catalogue. Units/language ambiguity remains reviewable. Human review is always required, and an NLP draft never confirms performed exercise. Existing deterministic meal/activity parsers, editable units/body-weight defaults, manual entry and optional separately authorized server AI remain unchanged. The synthetic tests are a development corpus, not independently authored held-out evidence.

`client/src/lib/description-intelligence.ts` exposes the requested `InterpretDescription(input,domain,context,signal)` boundary. It truthfully returns model-not-available: **no candidate model, runtime SDK, weights, tokenizer, licence review, download, offline-ready claim or active UI integration exists yet**. Capability probes report API presence only, not functional GPU/WASM support or model readiness. There is no new feature permission, toggle framework, backend route or canonical write. No actor/health context is sent to a model or validation worker.

The separate `validateCandidateInWorker` is an internal candidate/synthetic **source-validation** prototype, not inference. It uses a real dedicated same-origin worker, a131072-character candidate/4000-character source bound, one active job, cancellation/displacement, timeout/termination, source/actor-current callback withdrawal and initialization/unavailable fallback. The caller owns the original text and current-source callback, ties it to actual edit/navigation/account lifecycle, and must preserve fallback/manual review. It sends no API/provider request and writes no cache/training/storage. The module is not imported by normal app entry points; its worker is tested with Vite development assets, not claimed as a production-packaged model runtime. The3-second validator timer is a prototype bound, **not a selected model/device performance budget**.

Verification: four new grouped source-contract tests plus existing household-portion/mixed-activity consumers (11 tests), strict TypeScript/build/source guards. Actual Chromium dedicated-worker test validates drafts/refuses invented quantity, cancels, withdraws stale source/throwing actor callback, displaces an older job, handles missing Worker/malformed JSON and injected constructor/timeout faults with termination. Injected broker faults are distinguished from real worker execution; no physical device, inference latency/memory/battery or independently measured quality is claimed.
