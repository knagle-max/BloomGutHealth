## Core usability principle — useful without hunting or repeated entry (owner directive, 2026-11-18)

**User effort is a product defect to minimize, not an inevitable requirement.** If a user must search to discover a routine feature, repeatedly re-enter facts Bloom already knows, navigate deeply to correct a common field, or fill in many forms before receiving value, most users will abandon the workflow. **Bloom should do the safe, justified work on the user's behalf** and surface relevant information/actions at the right moment: clear navigation and contextual entry points, one obvious path to update shared report/profile information, concise first-run setup, reusable saved preferences/sources, prefilled known facts, and minimal, well-timed questions only when the answer materially changes an outcome. Prefer one correction at its true source that propagates to all authorized dependent views rather than per-marker/per-screen repetition. Whenever a new feature or materially changed screen is built, check **discoverability, time-to-first-value, steps/taps, repeated entry, reusability of confirmed data, persistence and user correction**. Move technical settings and deep scientific controls behind progressive disclosure, but ensure core entry/correction actions are readily visible without searching.

**“Just works” does not permit invention:** auto-import/derive/reuse only trustworthy, correctly scoped existing source data with current account ownership, version, timestamp and applicable consent; distinguish source-confirmed from inferred/estimated/unknown. Never infer a laboratory, test method, diagnosis, stage, dose, product, medication taken, food consumed, pregnancy or clinical action simply to remove a step. Prefer safe reversible defaults and suggestions for uncertain context, with a **single simple confirmation only when necessary**; saving a label does not record consumption. User must be able to inspect, edit, revoke and delete; privacy/safety/rights and consequential actions remain explicitly authorized. Background refresh/auto-sync only where existing permissions, provider capabilities and reliable source revision safeguards actually permit it. Keep workflows useful even with incomplete profiles, no connected devices or no AI.

**Codex autonomy:** reduce real friction as part of ordinary implementation without asking for a separate design approval; reuse canonical shared context, metadata, import and form components instead of inventing another platform. Report only material user-effort improvements and real exceptions concisely. No new audit bureaucracy, mandatory screenshots or competing `NEXT_ACTIONS.md` queue.

An external hold is feature-scoped. Move to next independently actionable approved task.
- **Progress, not busywork**: reuse current services/assets/identity and source contracts; do not reimplement a second safety engine, AI scientific authority, lab source ledger, food database, consent system or image renderer. Don't repeatedly re-review solved source rows, unchanged fixtures, prior asset transfers or old approval debates.

Do not weaken security/science or omit required assertions to escape a blocker.
- **Validation proportional to risk**: run focused relevant tests, typecheck/build as appropriate during work; full regression for shared high-risk boundaries or major integrated/release checkpoint, not repeatedly for the unchanged SHA/config/environment. A failed necessary check remains failed until corrected; never fake PASS. Once relevant tests and source audits pass, push a coherent slice, check exact CI/Render SHA once; if a remote verification is temporarily unavailable record `IMPLEMENTED_PENDING_DEPLOY_VERIFICATION` and do other independent work.
- **Concise session handoff:** `HEAD / current task+exit / completed exact SHA+tests / true blockers / next 2–3 independent tasks`. Put new results in the appropriate dated verification receipt; **do not prepend long chronological reports to `NEXT_ACTIONS.md`** or update five overlapping decision documents after every small fix.

## 5. When to stop or escalate

Stop only **the specific unsafe/disallowed action**; defer the blocked feature and select another safe one. When no meaningful independently actionable work remains in the current session or execution limit is reached, leave a clean exact-SHA receipt and concise remaining queue; do not manufacture further work or promise asynchronous progress.

**Do not request intermediate owner approval** for established project requirements. Request action only for an actual credential/account, paid service, sensitive data release, protected deployment or public release, native signing/device or genuine unresolved owner product choice. **Never ask for per-image or per-slice owner review.**
