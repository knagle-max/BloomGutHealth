# Previous saved routine versions

A changed experiment/routine record saves the prior encrypted payload and its original record timestamps in experiment_versions in the same locked transaction as the current update. Exact no-op retries add no fictional version. Snapshots preserve the previous source values, date ranges, unit/method, adherence, confounders, rationale and reflection; they are never additional active observations. Earlier overwritten values that were never captured cannot be reconstructed. The UI offers read-only history, current-value correction and explicit parent deletion; correcting a date retains its position and other observations.

Ownership follows the source parent. Reads join against the authenticated account and experiment kind; foreign/missing sources return404. There is no independent history edit/delete API. SQL blocks UPDATE, independent DELETE and TRUNCATE; deleting the parent or account cascades its history. A failed current update rolls back the history insert. Original ciphertext/key identifiers are retained, with account-bound authenticated decryption. A missing/decryption/error/oversized history is not displayed as an empty archive. Reads are bounded to50,000 rows/20MiB and fail rather than return a truncated source archive.

GET /api/experience/records/:id/history and the private workspace/account exports expose captured versions with source record ID and timestamps. The production workspace export reads settings/current records/history in one read-only repeatable-read transaction, preventing a correction between separate reads from mixing source versions. The account archive remains a read-only, bounded, complete-or-fail owned snapshot. Review/export distinguishes current source from prior versions and repeats the existing self-report/non-causality limitations. Versions do not enter Today/planning/Progress computations or authorize clinical/research inference. UI reads are owner scoped, withdrawn while stale/paused/failed and cleared across account changes; no external image/model/service receives this history.
