# Atomic spend ledger foundation

The text execution guard now wraps ingredient parsing, recipe ranking, recipe generation and optional science action ranking. No reviewed runtime executor is installed, so these paid calls default deny and manual/curated alternatives remain available. Do not claim all providers or full economics governance complete. Science coaching also requires its independent source clearance; photo execution remains separately gated. No production migration or monetary policy was configured.

`SpendLedger` accepts server-owned account/request identity, fixed feature/provider/model and tariff reference, an integer reservation in millionths of USD and explicit positive daily/monthly/concurrency limits. There are no invented monetary defaults. Missing/invalid limits deny. The caller must authorize the capability and consent, validate current tariffs and billed-unit bounds, and persist any provider request identifier before execution. Callers must execute only a **new** reservation (`replay:false`, `state:reserved`); a replay returns its prior state and must never make a second provider call. The ledger is not a job executor or response cache.

`postgresSpendTransaction` acquires one transaction-scoped PostgreSQL advisory lock, shared by every reserve/settle on every replica. A modest global lock is deliberate for current scale. Transaction rollback prevents partial updates. Use the same dedicated, stable secret on all replicas: changing it changes pseudonyms and would bypass historical account accounting, so rotation needs an alias/migration policy before runtime adoption. Neither client headers nor client budget values are accepted by this module. No HTTP/admin endpoint exists yet.

Reservations cover account UTC day/month, account feature/day, provider/month, platform/month and account/platform in-flight counts. Outstanding earlier-window reservations stay liabilities. Reconciliation uses settlement time conservatively for current-window accounting rather than silently forgiving late charges. Actual overages are recorded in full and block later reservations. A charge may be labelled actual only with trustworthy provider billing units; estimates remain explicitly estimated. This is not an invoice matching system. Settlement conflicts throw; repeated identical settlement is idempotent. Release is permitted only when execution is known never to have started. A timeout/crash with unknown provider outcome stays reserved until authoritative reconciliation; no automatic expiry or refund. Delayed completion must not be recorded as zero to free allowance.

The additive migration is applied only by explicitly isolated PR CI, with the matching Drizzle definition. Application startup does not migrate the existing Render database. The guarded Neon smoke uses separate pool connections, synthetic identifiers and test micro-unit allowances, and deletes only its own random feature rows. No provider calls, prompts, credentials, health payloads or real tariffs enter this smoke. Embedded PostgreSQL tests verify limits, account independence, retries/settlement, overage, pre-execution release, UTC reset, unresolved liability, invalid configuration and storage failure. Real Neon CI results must be recorded separately after publication.

Remaining before runtime use: reviewed effective-dated model/unit tariffs and budget policy, maximum billable-unit reservation bounds, authenticated callsite integration, provider request/usage receipts, retry/streaming/cached token reconciliation, stale-tariff denial, provider/global circuit breakers, cancellation/crash recovery, private aggregate reporting/alerts, stable identity-key recovery/rotation and reviewed pseudonymous accounting retention/deletion. The lock and integer ledger alone do not satisfy those requirements. Removal: retire consumers before dropping additive objects; never erase unresolved reservations as a rollback shortcut.

## Provider-unit costing contract

server/ai-costing.ts normalizes the installed OpenAI Responses usage shape (input/output totals and cached input breakdown). Cached input is included in input total, and reasoning belongs within output total; neither is added again. Missing cached breakdown, inconsistent total, negative/fractional or oversized units are unknown. The caller must retain the reservation or explicitly label a conservative estimate, never mark fabricated actual cost. Effective-from/expiry and exact model/provider/reference apply to each tariff; no tariff is bundled. Integer arithmetic sums all categories then rounds up once to whole micro-USD. Pre-execution reservations take no assumed cache discount and use the worst input rate. Token bounds still require a verified tokenizer/model request contract, not characters-to-tokens guesses. This module does not enable any current SDK callsite.

## Runtime text execution and receipts

`metered-ai.ts` requires server-sourced account/request identity, explicit consent, feature/account authorization, current pinned-model tariff, reviewed maximum serialized-request/input-token/output-token bounds, and shared monetary reservation. No bound is guessed from character counts. There is no client/environment boolean to install an executor. Actual composition/activation awaits reviewed inputs and infrastructure/key readiness; no live executor or migration was provisioned. Availability is per-account/per-feature and does not expose unready AI controls.

The four text SDK adapters execute only through this guard with retries disabled. Only text messages and the existing format schema are accepted; tools, images, hidden previous context, streaming, background execution and additional samples are denied. The guard forces store=false and the reviewed output cap. It rejects replay, rechecks payload/policy/authorization before invocation and authorization/runtime revocation before returning output. Disabling/replacing a runtime invalidates old executor instances. Once invocation starts, error/timeout/missing usage/model mismatch retains the reservation, rather than claiming a refund. Known pre-execution revocation can release it.

Successful usage settles against the tariff valid at invocation time, preserving the reviewed snapshot even if policy changes later. Full actual overages are recorded and output withheld. Settlement must succeed before any output returns. Additive migration 0010 records only token counts plus an account-scoped HMAC of the provider response ID, atomically with settlement; it stores no prompt, health payload or raw provider ID. Repeated same receipt is idempotent, conflicting counts reject. Isolated CI checks receipt storage too.

## Shared circuit admission

`SharedProviderCircuit` is a mandatory executor dependency. Its explicit provider/platform policies have no defaults; state is PostgreSQL-only and uses the same transaction/advisory-lock strategy as the ledger. Closed calls can proceed; threshold or provider-level auth/quota/rate failure opens a cooldown. One recovery probe is leased after cooldown. Generations fence old results and replaced/crashed probes, so stale success cannot close a newer outage. Cancellation before execution clears only its probe, never fabricates recovery. Provider state stores no account, health, prompt or raw error.

Circuit denial releases only the just-reserved unstarted monetary operation. Failed started operations keep their liability. Database failure denies provider execution. Streams/tools and other unpriced operations remain unsupported; runtime installation still absent. Circuit policy is intended for the existing shared server provider credentials, not user-specific credentials/errors. Actual 20/25-second SDK timeouts remain; leases require explicit review and minimum 30 seconds in this implementation. 243 tests/types/build passed locally; isolated Neon smoke now verifies one recovery probe across connections. No live migration or circuit activation claimed.

## Private operator cost report

Run `node --import tsx scripts/ai-spend-report.ts` only in an approved operator environment with `BLOOM_SPEND_REPORT_DATABASE_URL` set to a dedicated read-only credential limited to the ledger. The script deliberately never falls back to application DATABASE_URL, never invokes providers, and never settles/releases reservations. No live database was queried to develop this report. Missing schema/credential returns a fixed safe error. `--help` requires no database.

The bounded repeatable-read read-only snapshot returns current UTC-month actual and estimated settlements separately, all outstanding reservations (including older windows), outstanding count/age and provider/feature aggregates. Counts/amounts are exact integer strings. Average settled cost is an exact numerator/denominator over distinct settled **metered AI accounts**, not all app users; an empty denominator remains zero, not a fabricated average. Account/request hashes, raw IDs, provider receipts, prompts and health data never leave SQL. Aggregates are private operator information, not a public endpoint. No frontend admin role or monitoring schedule is provisioned.

Optional `BLOOM_SPEND_REPORT_ALERT_POLICY` is JSON with exactly `platformMonthlyMicroUsd` (positive integer string up to 1000000000000), `thresholdPercent` (1–100 integer) and `unresolvedAfterSeconds` (1–31536000 integer). These must be reviewed values, never guessed defaults. At/above the budget percentage or outstanding-age threshold, structured alert codes are returned and the CLI exits 2. Failure exits 1; unconfigured monitoring is explicit. Nothing sends email or other notifications. Attach this command to existing authorized operator monitoring only after deployment/environment review.

Outstanding reservations may represent in-flight calls or unknown billing, so an age alert requires investigation, not automatic refund. Trustworthy provider/invoice evidence is still required for reconciliation. Aggregate liabilities cannot identify a particular failed provider call and do not claim invoice accuracy. Reconciliation/configuration/retention/identity-key operations remain independent unfinished work.

## Offline configuration review and trusted composition

`node --import tsx scripts/check-ai-policy.ts < reviewed-policy.json` validates a bounded JSON document without reading environment credentials, querying a database, calling a provider or installing an executor. Output says structurally valid/current and approval NOT_VERIFIED; review references are not proof of approval. Invalid input yields a fixed safe error without identities, prices, policy values or secret echo. Keep policy documents private: they contain account grant identifiers. Never put secrets in this document (unknown fields are rejected).

The strict versioned schema in server/ai-configuration.ts requires explicit shared limits, pinned current model/tariff, complete-request byte and token bounds/review, both circuit scopes and uniquely expiring account/feature grants. No monetary defaults, inferred tokenizer bounds or inherited internal-UI permissions. Policy/tariff/grant dates must align; per-call worst-case reserve must fit every shared allowance; contradictory hierarchies and duplicate scopes fail. The 2 MB serialized-request ceiling is a capacity restriction, not a token estimate.
