# Atomic spend ledger foundation

This foundation is not connected to live OpenAI calls and does not enable providers. Existing parser/recipe paths still require integration; do not claim all AI costs are controlled. Science coaching and photo remain separately gated. No production migration or monetary policy was configured.

`SpendLedger` accepts server-owned account/request identity, fixed feature/provider/model and tariff reference, an integer reservation in millionths of USD and explicit positive daily/monthly/concurrency limits. There are no invented monetary defaults. Missing/invalid limits deny. The caller must authorize the capability and consent, validate current tariffs and billed-unit bounds, and persist any provider request identifier before execution. Callers must execute only a **new** reservation (`replay:false`, `state:reserved`); a replay returns its prior state and must never make a second provider call. The ledger is not a job executor or response cache.

`postgresSpendTransaction` acquires one transaction-scoped PostgreSQL advisory lock, shared by every reserve/settle on every replica. A modest global lock is deliberate for current scale. Transaction rollback prevents partial updates. Use the same dedicated, stable secret on all replicas: changing it changes pseudonyms and would bypass historical account accounting, so rotation needs an alias/migration policy before runtime adoption. Neither client headers nor client budget values are accepted by this module. No HTTP/admin endpoint exists yet.

Reservations cover account UTC day/month, account feature/day, provider/month, platform/month and account/platform in-flight counts. Outstanding earlier-window reservations stay liabilities. Reconciliation uses settlement time conservatively for current-window accounting rather than silently forgiving late charges. Actual overages are recorded in full and block later reservations. A charge may be labelled actual only with trustworthy provider billing units; estimates remain explicitly estimated. This is not an invoice matching system. Settlement conflicts throw; repeated identical settlement is idempotent. Release is permitted only when execution is known never to have started. A timeout/crash with unknown provider outcome stays reserved until authoritative reconciliation; no automatic expiry or refund. Delayed completion must not be recorded as zero to free allowance.

The additive migration is applied only by explicitly isolated PR CI, with the matching Drizzle definition. Application startup does not migrate the existing Render database. The guarded Neon smoke uses separate pool connections, synthetic identifiers and test micro-unit allowances, and deletes only its own random feature rows. No provider calls, prompts, credentials, health payloads or real tariffs enter this smoke. Embedded PostgreSQL tests verify limits, account independence, retries/settlement, overage, pre-execution release, UTC reset, unresolved liability, invalid configuration and storage failure. Real Neon CI results must be recorded separately after publication.

Remaining before runtime use: reviewed effective-dated model/unit tariffs and budget policy, maximum billable-unit reservation bounds, authenticated callsite integration, provider request/usage receipts, retry/streaming/cached token reconciliation, stale-tariff denial, provider/global circuit breakers, cancellation/crash recovery, private aggregate reporting/alerts, stable identity-key recovery/rotation and reviewed pseudonymous accounting retention/deletion. The lock and integer ledger alone do not satisfy those requirements. Removal: retire consumers before dropping additive objects; never erase unresolved reservations as a rollback shortcut.
