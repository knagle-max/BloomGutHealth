## Web review and complete ingredient commands

The current web uses nonpersisting POST `/api/meals/review` and explicit POST `/api/meals/confirm`, both aliases of existing analysis/save handlers. For structured reviews, ingredients represent the complete meal; the original products array remains original-entry context and is not appended again to analysis. Confirmation requires the reviewed marker, complete ingredients and source precondition. New paths fail on older servers instead of falling back to an unreviewed write. Legacy analyze/save semantics remain compatible.

The web retains original text/context and canonical reviewed ingredient identities. Other generic foods expose their own source measures (cups, pieces, servings, etc.); there is no universal grams-per-serving conversion. USDA pizza `piece` is presented as `slice (piece)`. The source's `Quantity not specified` is explicitly labelled **estimated serving (source default)**, never a measured serving. Unknown foods or unsupported measures remain unknown. Grams and existing printed product-label servings remain available.

The additive ingredient `household` field retains the matched FDC source, available measures, selected label and quantity alongside canonical mass. The server rebuilds choices from the bundled source and checks selected portions; submitted option weights cannot replace source weights. An older client editing canonical grams retracts incompatible household metadata instead of blocking a valid mass correction. Original meal text stays unchanged; changing a food withdraws its old portion choices. Templates scale household quantities along with mass.
