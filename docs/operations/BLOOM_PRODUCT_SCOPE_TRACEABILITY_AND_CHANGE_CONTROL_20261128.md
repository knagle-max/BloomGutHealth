## No-loss change control for future queue compression and Codex task selection

**When changing `NEXT_ACTIONS.md`, `AGENTS.md`, full v0.6 classification or the contract map in a materially scope-altering way:**
1. **Preserve the prior bytes first** with a dated immutable archived snapshot / exact prior Git blob; record source hash, length, and verify exact content equality before replacing.
2. **Review the 116-family baseline, 152 scenario-group index and later owner delta table**, plus new owner directives since the last reconciliation. Explicitly classify *any* affected item as `ACTIVE`, `NEXT`, `SPECIFIED`, `PARTIAL`, `IMPLEMENTED_ENGINEERING_VERIFIED`, `DEFERRED`, `BLOCKED_BY_REAL_DEPENDENCY` or `SUPERSEDED_BY_EXPLICIT_OWNER`. Do not treat archived-only location as effective next-work discoverability.
3. **Compare capabilities, not keyword presence.** Every scoped feature needs a reachable authoritative contract and actionable triggering path (queue row, domain handoff or dependency classification). New product scope must appear in the relevant domain contract and be **indexed here**; status/date/evidence separate from priority.
4. **Failure if an approved family or amendment is not reachable from this index** (or newly documented with a precise traceable source), if its last applicable acceptance disappears, or if a status silently switches to DONE/DEFERRED/CANCELLED without authentic proof or owner supersession. Restore the link/status before committing.
5. **Keep `NEXT_ACTIONS.md` short.** It may list one selected task, bounded candidates, and this single preservation index. Detailed acceptance and source evidence remain in canonical handoffs, 116-family audit, 152-case master catalog, and their original immutable archives. The index does **not** select Codex work.
6. **No routine 116×152 exhaustive audit per code commit.** Check only the affected rows and original requirements during a normal coding task; perform broad coverage reconciliation only on actual scope compression, important new parent amendments or integrated RC review. Never turn preservation governance into another Codex documentation loop.

### Distinct proof/status rules

- `IN_SPEC` / `COVERED_BY_CONTRACT` = requirements preserved.
- `IMPLEMENTED` = current actual source/feature present, narrow claim only.
- `ENGINEERING_TESTED` = tests and authentic browser proof for the claimed scope.
- `INDEPENDENTLY_REVIEWED` = actual separately approved Brand, scientific, Security, Clinical, Legal, rights/quality or other specific review.
- `CONSUMER_AUTHORIZED / HOSTED_VERIFIED` = independent release/exposure/hosted evidence as appropriate.
- `DEFERRED` and `GATED` retain requirements until an authorized successor; no inferred cancellation.

**Out-of-scope:** The register is a source-preservation/navigation invariant, **not** evidence that every feature was compared at acceptance-ID level or implemented. A future independent full gap audit may be useful at integrated RC. Current Codex must continue coding the one `NEXT_ACTIONS.md` active task, not pause for a full taxonomy sweep.
