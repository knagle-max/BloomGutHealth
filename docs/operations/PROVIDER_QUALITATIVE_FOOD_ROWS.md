# Provider qualitative assessments and food rows

The existing canonical `bloom-report-v2` parser now supports optional `foods` (or legacy `food_recommendations`) as an array of source rows. Each normalized row has name, nullable reportedCategory/notes and nullable sourcePage/sourceColumn. Names/categories remain literal; unknown values stay null. Malformed rows, excessive lengths and more than1000 rows fail without truncation. Repeated names remain separate rows in original order. Source data is retained using the existing account-scoped canonical import, atomic save receipt and export contract; there is no second report or food-planning store.

The report view displays a qualitative category directly when no numeric value was supplied. It does not calibrate Improve/Attention/Maintain into numbers. Food suggestions expose provider attribution, original label/category, search, category counts/filter, ten initial rows, Show all and progressive source-position/notes. General interpretation limits remain available in a disclosure, with the key limitation visible. “Avoid” is not an allergy, hard exclusion, nutrient target or personal action rule. No planner/ranking/allergy/clinical-model input changes.

Reader compatibility projects recognized food rows from an older report's retained source when the canonical field was never present. An explicit canonical empty array takes precedence and cannot resurrect prior rows. Malformed legacy formats produce a truthful unavailable message without modifying source data. Search/category state resets on source change. Current report ownership and source-denial withdrawal remain enforced by the existing route/query boundaries.
