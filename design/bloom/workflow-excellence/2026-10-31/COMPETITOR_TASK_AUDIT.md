## Design assumptions / action budgets (not observed competitor values)
- Bloom Athlete tap target from Athlete landing: Start saved workout ≤2 taps. From active set screen: edit load one field tap + numeric entry + Done; complete set 1 tap; next exercise visible without navigating a hidden accordion; Finish→Review→Save 2 taps.
- Bloom Everyday: full existing set editor preserved; no muscle or calorie panel by default.
- Today: one current insight, two direct entry points (Log food, Log workout) and no unverified health score.
- Biology: marker category → dated series in ≤2 taps; source/corrections one action from detail.
- Instrument actual counts with fresh production-equivalent app and devices before labeling PASS.

## Friction and design risks (analysis rather than demonstrated defects)
- Excess menu nesting for a frequent exercise action adds high repeated interaction cost.
- Leaving previous-set reference unlabeled can cause historical value to be mistaken for saved current set.
- Automatic finish without explicit review risks incomplete set loss.
- Forced numeric nutrient/biomarker summary conceals missing data.
- Plan/workout analysis conflation can double-count wearable sessions.
